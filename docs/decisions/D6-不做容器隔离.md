# ADR-D6：不做容器隔离

> 状态：待确认
> 日期：2026-09-20
> 关联：`docs/architecture.md` 第 1 节 D6、第 6 节
> 相关：ADR-D5（本决定是 D5 的直接前提）

## 背景

Pi 在无内置权限弹窗的前提下，把容器隔离作为推荐的硬边界。
sigma 是否需要照做？

约束：开发环境是 Windows，单人开发，学期中约 8 小时/周。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 做容器隔离 | Docker / micro-VM / seccomp 白名单 | 唯一真正意义上的硬边界 | ① Windows 上 Docker 的开发体验与启动开销对单人项目是纯负担<br>② 容器内调试会显著拖慢 P1–P4 的迭代速度<br>③ 需要维护镜像、挂载、凭证注入<br>④ 会占掉相当一部分时间预算 |
| B. 不做，明确声明 | 不提供容器，只在文档里写明边界 | ① 保留全部时间用于架构与评测<br>② 「明确声明边界在哪」比「假装有隔离」更专业 | 宿主环境完全不受保护 |

## 决定

**选 B：不做容器隔离，并在 `README.md` 与 `docs/architecture.md` 中明确声明。**

## 后果

**变好的地方：**
- 开发迭代速度不受容器拖累。
- 文档里那句「宿主环境不受保护」本身是设计成熟度的证据——
  它证明作者知道自己的边界在哪。

**变差的地方：**
- **无法声称自己是「安全的 agent harness」。** 这句话在面试里不能讲。
- 演示时只能在受控目录里跑，不能在产品代码库上跑。
