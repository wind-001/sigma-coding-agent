# ADR-D1：实现语言选 Python

> 状态：**部分确认**（语言已拍板，首个 Provider 已拍板 a3，代价栏待填）
> 日期：2026-09-20
> 关联：`docs/architecture.md` 第 1 节 D1、第 3 节、第 2.2 节

## 背景

参照对象 Pi Agent Harness 是 TypeScript monorepo。sigma 需要选一门实现语言。
约束条件：单人开发、学期中约 8 小时/周、既有技术栈为 Python（FastAPI / Pydantic /
SQLAlchemy / pytest）、已有另一个 Python 项目在并行维护。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. Python | 用既有栈实现 | ① 既有能力直接复用，不新增语言成本<br>② Pydantic 模型可直接生成工具参数 JSON Schema，比 Pi 用的 typebox 更贴合已有经验<br>③ `pytest` / `import-linter` / `mypy` 的用法已在另一项目验证过<br>④ 国内 AI Agent 应用工程岗 Python 占主导 | ① 拿不到 Pi 的 jiti 式零构建热重载，需自行设计<br>② 拿不到 Pi 的源码级参考，只能抄设计 |
| B. TypeScript | 与 Pi 同语言 | ① 可直接读 Pi 源码<br>② 热重载机制有现成范式 | ① 新语言 + 新领域同时学，8 小时/周的预算下是净亏损<br>② 既有栈全部作废，等于从零开始 |

## 决定

**选 A：Python。**

**2026-09-20 拍板（a3）：`AGENTS.md` 第 2 条「采用继承制」适用于全项目接口设计。**
具体影响：

| 位置 | 写法 |
| --- | --- |
| `Provider` | `BaseProvider(ABC)`，子类 `OpenAICompatProvider` |
| `Tool` | `BaseTool(ABC)`，子类 `ReadTool` / `WriteTool` / `EditTool` / `BashTool` |
| `Hook` | `BaseHook(ABC)` |
| `Store` | `BaseStore(ABC)` |
| `Loop` | `BaseLoop(ABC)`，**当前只有一个子类** `AgentLoop` |
| 数据载体 | `Message` / `Usage` / `ToolCall` / `ToolResult` / `ToolContext` / `StreamEvent` 一律 Pydantic `BaseModel` |

**不用 `typing.Protocol`。** 理由：Protocol 是结构化类型，不产生继承关系，
忘实现抽象方法时只在"首次调用"暴露，而 ABC 在"实例化"就抛 `TypeError`。
「后期扩展」这个诉求下，早暴露远比晚暴露重要。

首个子类落地顺序：P1 只做 `OpenAICompatProvider`（覆盖 DeepSeek / Kimi / GLM /
通义 / vLLM / Ollama / LM Studio），`AnthropicProvider` 进 P4 之后。

## 后果

**变好的地方：**
- 项目从第一天就能写业务逻辑，不需要先付语言学习成本。
- 评测框架的设计模式可以从另一个项目迁移。
- Pydantic 让工具参数 schema 的写法比参照对象更自然。

**变差的地方：**
- 失去 Pi 最亮眼的那个能力（agent 改自己的扩展、当轮生效）的原生实现路径。
  D3 因此把扩展能力主动收窄。
- Python 的热重载有真实正确性风险（模块级状态、旧引用不更新），
  这部分需要额外设计和单测覆盖。
