# ADR-D7：目录结构按功能域重组

> 状态：已确认（星辰 2026-09-29 逐项拍板，见详规 §7）
> 日期：2026-09-29
> 关联：`docs/plans/P6-目录结构重构-详规.md`、`docs/architecture.md` §3 / §8

## 背景

P0 定下的五包布局（`core/` 下 sigma / sigma_ai / sigma_agent / sigma_session / sigma_tools
平级）在四个批次的演进后暴露三个问题：

1. **包名是"层名"不是"功能名"**——面试官或新读者无法从目录名读出系统做什么；
2. **同域概念分裂多处**：技能系统三处（agent/skills、session/resources、tools/skill）、
   钩子事件与总线同居一处、系统提示词埋在 sdk.py 中间、观测层分居两会话相关包；
3. **`_` 前缀私有模块不达意**：`_paths`（实为路径沙箱）、`_approval`（实为审批门）。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | 保持五包，只改内部文件名 | 零迁移成本 | 三个问题一个不解决 |
| B | 照搬朋友简历布局（config/agent/runtime/... 顶层平级包） | 与简历叙事一致 | 顶层裸名易碰撞、无命名空间、且会虚构不存在的目录（infrastructure/redis） |
| C（选定） | **单顶层包 `sigma`，src/ 布局，内部按功能域分 15 子包**，import-linter 层表重写 | 功能域目录名 + 层契约都保留；无虚构目录 | 一次全库搬迁（127 文件 import 改写） |

## 决定

选 C。包结构见 `docs/plans/P6-目录结构重构-详规.md` §2.1，新层表见 §2.2。

## 后果

**变好的地方：**

- 目录名与简历叙事对齐（runtime / providers / events / hooks / tools / skills /
  sessions / memory / security / observability / prompts / config）；
- 五条已知缺陷逐条落地修复（events-hooks 边界、双"压缩"分家、prompts 独立、
  装配层显式化、可观测层成包）；
- import-linter 层表更细（15 层），依赖方向约束更强。

**变差的地方：**

- 一次搬迁 127 文件的 import，git 历史在文件级间断（git mv 保留了 rename 追踪，
  但 blame 跨批次要 `-M` 选项）；
- 文档中大量 `sigma_agent.xxx` 引用成历史（architecture.md 各批次变更记录保留原文，
  只更新"现行"章节，历史不做篡改）。
