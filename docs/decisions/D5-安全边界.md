## 背景

Pi 的默认姿态是**宽权限**：信任提示通过后，agent 就能用完整工具读写执行，
没有内置权限弹窗。它的替代方案是容器隔离。

sigma 不做容器（见 ADR-D6），因此必须有别的边界。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 不做边界 | 完全依赖使用者自觉 | 零成本 | 危险操作可不可控 |
| B. 只做钩子规则 | 用字符串匹配拦危险命令 | 实现简单 | **可靠性低**，编码绕过、脚本分步执行都能绕过，且无法量化 |
| C. 三层软边界 | ① 工作区根目录约束<br>② 影子 git checkpoint（每批次前提交，可整体回滚）<br>③ 钩子规则 | ① L1/L2 可靠性高且可证明<br>② checkpoint 让「可恢复性」成为可量化指标（回滚成功率、恢复后成功率）<br>③ 不假装有沙箱 | 需要一个影子 git 仓库与清理逻辑 |

## 决定

**选 C。三层边界，并在 README 与架构文档中明确写出钩子挡不住什么。**

影子 git 的实现约定：

```
GIT_DIR       = <session_dir>/shadow.git
GIT_WORK_TREE = <workspace_root>
```

**关键点：不碰用户仓库自己的 `.git`。** 用独立 `GIT_DIR` 是唯一不污染真实提交历史的做法，
`git stash` 和往用户历史里插 commit 都会污染。

## 后果

**变好的地方：**
- 「能不能恢复」变成可测量的数，而不是「我加了权限检查」这种不可验证的说法。
- 破坏性操作的影响面从「不可逆」降为「可回滚」。

**变差的地方：**
- 需要处理几个必须处理的边界情况：文件删除（`checkout <commit> -- .` 不会删除新增文件）、
  大文件上限（否则 checkpoint 会拖慢）、`.gitignore` 的 exclude 源（否则会把依赖目录提交进去）。
- 每次写批次多一次 git 提交，有性能开销。
