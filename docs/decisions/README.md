# 架构决策记录（ADR）

每份 ADR 记录一个**不可轻易反悔**的决定。

## 为什么要有这栏

`AGENTS.md` 第 5 条要求关键决策需征询本人。ADR 是这个要求的落地形式：
决策不能只留在对话里，必须落成文件，且必须包含「判断依据」和「我接受的代价」两栏。

**这两栏不接受由 AI 代填。**

原因很直接：作品集的风险不在功能多少，而在**项目的技术深度超过本人可自证的深度**。
一个自己写不出取舍理由的架构，在追问面前会直接塌掉。
AI 可以把「背景 / 选项 / 后果」整理清楚，但「我当时为什么这么选」只能由本人回答。

如果某份 ADR 的两栏是空的，那这份 ADR 视为未完成。

## 流程

1. 复制 `template.md`，按 `D<编号>-<短名>.md` 命名。
2. 填写「判断依据」与「我接受的代价」。
3. 把状态改为「已确认」。
4. 若后续推翻，不要删除——把状态改为「已废弃」并新开一份，
   这样能看出决策的演化过程。
