# ADR-D8：收敛权的归属——从「模型独占」到「可插拔」

> 状态：待确认
> 日期：2026-10-13
> 关联：`docs/architecture.md` 第 2 节（agent loop 的八步）· `docs/plans/推进机制-详规.md` §3

## 背景

sigma 的 `run_turn`（全项目唯一实现，`runtime/event_loop.py`）今天这样决定
"任务结束"：**模型不再调工具 → 信箱空 → `status="completed"`**。
也就是说，收敛权完全由模型独占——它说做完了就是做完了。

这个决定在"约束优先"的阶段是对的：harness 不猜任务意图，一切以模型行为为准，
可审计、可回滚、可证伪。但它带来一个结构性问题：**当模型过早收手时
（症状 A：一收手任务就结束，不会自己发现还没做完；症状 E：每条任务都要人喂），
系统没有任何合法的干预通道**。既有刹车机制里，注入点只有
todo steering 与停滞 nudge，两者都只改上下文、且文案均为纠错；
"是否还有下一轮"由模型独占。

2026-10-06 的症状认领（星辰）+ 2026-10-13 的 B1 基线实测（agency 评测轴，
见推进机制详规 §1）把这个问题从体感变成了数字。本 ADR 决定这个权力的归属。

## 选项

| 选项 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A | **维持模型独占**：收手即 completed，harness 不干预 | 语义最简单；"harness 不猜意图"的纪律最纯粹；零新增失败面 | 症状 A/E 无解；谎报完成（status=completed 而验收判据不成立）永远无法被系统发现；每条任务都要人喂 |
| B | **harness 独占**：完成后强制跑验收判据，不过就不许 completed | 根治收尾幻觉（F4）；判据客观（pytest/清单） | harness 需要知道"任务的目标是什么"——任务契约扩展（verification_cmd）；任务不声明命令时无从判断；把"完成"的定义权从模型拿走，与 D2 的边界精神有张力 |
| C | **可插拔（本题决定）**：收敛权从模型独占改为"模型提案、客观判据可否决"——模型说完成是**提案**；第三方扩展面（AdvanceHook）可依据客观判据（清单未清空/验收命令未过）否决并继续一轮；不注册扩展时行为与今天逐字节一致 | 症状 A/E 有解；判据客观可证伪；零注册=零行为差（沿用 hooks/base.py 既有承诺）；自主性是**可增长的**——新判据不用改 loop | 多一个决策型钩子面（第三个）；"继续"可能被滥用成死循环（用每条机制自带的上限封顶）；任务的"完成"语义变复杂：completed 从"模型说完了"变成"模型说完了且没人否决" |

## 决定

选 **C：可插拔**。收敛权的默认状态仍是"模型说了算"（不注册推进钩子时行为
与今天逐字节一致），但**默认状态不再是没有选项的状态**——`AdvanceHook`
（第三类决策型钩子，与 ApprovalHook 同模式）让"这一轮还不算完，继续"
成为可注册、可关断、可证伪的机制。判据只认客观事实（todo 清单有 pending、
验收命令未通过），"我觉得没做完"不是判据。

## 后果

**变好的地方：**

- 症状 A/E 有了合法的干预通道，且每条通道有自己的开关与注入实验（推进机制详规 §8）。
- "harness 有用"与"工具本身有用"的归因更干净：agency 评测轴（M1–M5）可以量化
  每个推进机制的边际贡献（关掉它，任务会不会提前收束或走得更保守）。
- 收敛语义的分层变清晰：模型提案 → 刹车判定（既有机制）→ 客观判据否决（新增）
  → completed。

**变差的地方：**

- 第三个决策型钩子面：总线从两类变三类，`HookManager` 的询问协议多一套
  （注册/重名拒绝/询问语义都要与既有两套对齐并被测试钉住）。
- "继续一轮"是新的行为面：误判的继续会烧 token（每条机制自带连续上限封顶，
  且推进永远问在刹车之后——被停的任务不会因它续命）。
- 任务契约若扩展 `verification_cmd`（M-B），CLI/工作台/SDK/评测四处传链都要改，
  且"完成"的判据出现第二个事实源（模型自陈 + 客观命令）。

## 何时应该重新考虑

1. **A/B 数字证明推进机制没有净收益**：关掉机制后 agency 轴（M1' 谎报完成率 /
   M4 自发推进率）不变，而多跑的轮数是实打实的成本——那么"可插拔"应该退回
   "模型独占 + 仅保留提示词引导"。
2. **"继续"被滥用**：线上观测到推进钩子连续打满上限（3 轮）仍无进展的会话占比
   超过两成——判据设计错了，该收尊重定。
3. **出现第四个决策型钩子需求时**：总线三类变四类是重构信号（询问协议该统一为
   一张判定表而不是三个并列方法），那时重开 ADR。
