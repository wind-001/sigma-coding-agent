## 1. 范围判断(为什么是"只读桥接"而不是 σ-server)

σ-server(FastAPI + SSE + 执行环,`sigma-frontend/docs/sigma-backend-api-design.md`)
是**待拍板的 M1/M2/M3**——五条决策点(服务位置/存储/事件通道/流式粒度/鉴权)一个都没拍。
本次不做 σ-server;做**契约的只读子集**:sigma 现在真实拥有的数据面
(会话 JSONL / 观测时间线 / 技能 / 记忆 / 内置工具)以既有契约形状读出来,
执行类端点 501 + 指路,前端相应控件标"待接入"——**功能没有后端依据的,标记而不是假装**。

## 3. 关键决策

1. **前端 Task = 一个 sigma 会话**。列表用 `session_previews`,详情整树解析——与 CLI
   `/sessions`、`--timeline` 同源,零二次存储。状态推导:trace 末轮落点 >
   悬空工具调用(中断,可续跑)> 正常收尾;`failed` 标签改"失败/中断"如实表达。
2. **契约不动,实现补位**:`client.ts` 接口只做**可选**扩展(`getTaskTimeline?`),
   mock 不实现、消费方判空调用——σ-server 将来按原契约落地不受影响。
3. **只读三道边界**(桥接 docstring):不执行扩展代码(插件清单不含 `extensions/*.py`
   ——装载即执行);不写任何文件(写动词一律 501);只绑 127.0.0.1。
4. **坏数据降级**:旧格式会话(v1.4 时间戳变更前)会让整树解析抛 pydantic 错——
   单会话跳过、不拖死列表,与 timeline 模块自述的查看器策略同一条。
5. **501 带指路文案**:`{detail: "...待接入(σ-server M2)..."}` 经 httpClient 原样进
   toast——用户点被禁用不了的路径时也知道为什么、差什么。

## 5. 执行环(2026-10-01 追加,星辰拍板"输入 → 新建会话 → 开始聊天")

第一版只读交付后,星辰指出输入无效不符合"工作台"直觉——**以现有功能为核心**,
把 σ-server M2 里能落地的最小切片做了进来:

- `POST /tasks` 建草稿(元数据仅内存;id = `new_session_id()`,执行后会话文件同名);
- `POST /tasks/{id}/messages` **同步跑一轮**:`resolve_api_key` + `builtin_providers`
  (与 CLI 同一条解析链,`SIGMA_PRESET`/`SIGMA_MODEL`/`SIGMA_BASE_URL` 可覆写)
  → 按线协议分派 provider → `run_task` 驱动 InteractiveSession——
  会话落真实 JSONL、断点续跑(`SessionTree.from_store`)、影子快照
  (`shadow_git_dir_for`,家目录自动禁)、trace 默认开(时间线端点拿到真值)。
- 并发守卫:同一会话同时只许一轮(409);未配 key 400 指路;执行失败任务标
  failed 但会话文件里已落的事实照常回放。
- 仍未接入:**审批交互确认(工具自动放行,L1/L2 在岗)**、打断/steering、
  流式增量、自动化、装卸——前端对应控件保持"待接入"标注。
- 验证:15 条桥接测试(假 provider 走真实 run_task/落盘/回放/timeline);
  真实烟雾:deepseek-chat 一轮对话全链路 ✓。顺带记录:curl 内联中文在
  Git Bash 会 GBK 化,冒烟要用 UTF-8 文件体(浏览器 fetch 无此问题)。
