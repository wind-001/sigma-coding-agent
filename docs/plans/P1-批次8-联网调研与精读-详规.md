## 0. 要解决的问题

批次 7 交付的 `web_search` 只有一句话的性格："把 Tavily 的结果原样倒给模型"。
后果有三条，都是可观测的：

1. **结果里混着广告站与内容农场**，模型要在同一段上下文里自己辨认，认错的代价是一次错误的结论；
2. **没有时间维度**：Tavily 摘要里的"2023 年的写法"和"上个月改的写法"在输出里长得一模一样；
3. **只有摘要，没有正文**：需要精读时模型没有工具可用，只能反复换搜索词碰运气（每次都花 credit）。

本次要加的，是"调研纪律"这一层。星辰给的政策文本（12 条）逐条落到下面这张表——
**判断交给模型（提示词），兜底交给代码（硬闸）**。

| # | 政策原文要点 | 落点 | 谁实现 |
| --- | --- | --- | --- |
| 1 | 只采信 Tavily `results`，**不采信 `answer`** | 删掉 `include_answer` 参数；响应里的 `answer` 字段**直接丢弃**（不是"默认关"，是**没有这个开关**） | 代码 |

### 0.1 为什么提示词之外还要代码硬闸

pi 笔记 13.2 把控制分成两类，结论是"**单独用任何一个都会坏掉**"：

- **Guides（前馈）** = 本次的政策文本 → 在模型行动前提高一次做对的概率；
- **Sensors（反馈）** = 本次的四道硬闸 → 在模型判断失误时兜住后果。

13.3 又给了选择依据：**计算型**（确定、毫秒级、便宜）该用在能用的地方，
**推断型**（LLM 判断）只在真正需要理解的地方用。政策文本依赖的是推测型判断，
所以黑名单、上限、计数这三件**不需要理解**的事，必须由计算型来做——
这正是星辰说的"提示词里的 LLM 判断仍然不可靠，代码加一层保护"。

**一道额外的闸（我加的，需裁决）**：进程内抓取上限 `SESSION_FETCH_CAP`。
"单次 2 条"只约束一次调用；一个跑飞的 loop 可以在 20 轮里花掉 40 credits。
全局额度（1000/月）到顶才停，太晚了——所以再加一层"这次会话总共最多抓 N 条"。
见 Q7。

### 0.2 不做的事（避免范围蔓延，沿用批次 7 的纪律）

- **不做** Firecrawl `search` 端点（2 credits / 10 条，比 Tavily 贵，且搜索职责已有归属）；
- **不做** `crawl` / `map` / `batch-scrape` / `agent`（递归抓整站 = 额度黑洞，也没有需求）；
- **不做**网页正文缓存（P1 无落盘能力；缓存会让"额度记录"与"实际请求"不再一一对应）；
- **不做**结果相关性打分模型（那是推断型工作，交给模型；代码只做能确定的事）；
- **不改** `web_search` 的记账与预留-结算语义（批次 7 的 G37–G41 全部保留）。

## 1. 关键决策（Q1–Q8，推荐值已给，待拍板）

### Q1 工具边界：**两个工具**，不是一个"内部自动精读"的工具

| 方案 | 判断 |
| --- | --- |
| **`web_search` + `web_fetch`（推荐）** | 搜索与精读各自是一个**原语**（pi 笔记 2 节：primitives, not features）。"要不要精读、精读哪条"由**模型**决定，代码只设上限 |
| `web_search` 内部自动抓 top2 | 把"判断"写死成启发式代码，与政策本身矛盾；一次调用混着 1 + 2 credits，`details` 无法分账；模型失去"不抓"的选择权 |
| 一个工具带 `fetch_urls` 参数 | 省一个 schema 的常驻成本，但把两条**计费不同、失败模式不同**的路径塞进一个 `try`，错误归一化会退化成"什么都报成搜索失败" |

推荐：**两个工具**。常驻区多付约 150 token，换来两条清晰的错误面与可独立开关。

### Q2 政策文本落在哪：**系统提示词（压缩版）+ 工具 description（操作级）**

- 系统提示词的"调研纪律"段（约 10 行 / 300 token）：**何时精读、如何引用、新旧冲突怎么办、找不到近期资料要说**；
- 两个工具的 description 只放**操作级**规则：额度口径、单次 2 条上限、黑名单与时间过滤会静默丢弃但会在输出里报数。

理由：D4 要求常驻区**逐字节稳定**，所以提示词仍然是**常量拼接**（`build_system_prompt(web_search=...)` 的既有形态），
不按查询动态变化。政策文本是常驻成本，**要量一次并更新 architecture 5.1 的预算表**（见第 5 节）。

### Q3 黑名单的内容（**这条最需要你裁决**）

判定规则：**注册域 + 子域匹配**（`csdn.net` 命中 `blog.csdn.net`），外加路径模式 `/forum/`、`/bbs/`、`/thread/`。
另有一张 `NEVER_BLOCK`（权威源永不被误伤）：`github.com`、`docs.python.org`、`developer.mozilla.org`、
`pypi.org`、`*.readthedocs.io`、`stackoverflow.com`、`stackexchange.com`。

| 类别 | 默认表（待裁决） |
| --- | --- |
| 低质 UGC / 问答 | `quora.com`、`answers.com`、`answers.yahoo.com`、`zhidao.baidu.com`、`tieba.baidu.com`、`wenku.baidu.com`、`ask.csdn.net` |
| 内容农场 / AI 生成 SEO | `geeksforgeeks.org`、`javatpoint.com`、`tutorialspoint.com`、`w3schools.com`、`programiz.com`、`runoob.com`、`csdn.net`、`jianshu.com`、`51cto.com`、`linuxidc.com`、`php.cn`、`itdaan.com`、`pianshen.com`、`codeleading.com` |
| 下载 / 广告站 | `download.csdn.net`、`xiazai.*`、`crx4chrome.com` |

**两处我要明确反对/提醒的**：

1. **StackOverflow / StackExchange 不进黑名单。** 星辰写的是"过滤论坛"，但 SO 是编程领域的**一手答案集**——
   大量报错只有那里有。把它当"论坛"过滤掉，等于把最有价值的来源删了。请确认这条例外。
2. **`csdn.net` / `cnblogs.com` / `runoob.com` 要慎重。** pi 笔记 0.5 与 1 节给了一个很硬的旁证：
   "**版本、包名、star 数在中文资料里几乎全是错的**"——这支持过滤 `csdn.net`（内容农场化最严重）。
   但 `cnblogs.com` 上仍有高质量原创；`runoob.com` 是很多中文开发者唯一的入门源。
   我的推荐：**`csdn.net` 进黑名单，`cnblogs.com` / `runoob.com` 不进**（保留，靠时间预过滤削峰）。

### Q4 时间预过滤：**`MAX_RESULT_AGE_DAYS = 730`（2 年）+ `include_old` 逃生阀**

- 从 title + content 抽日期（绝对：`2026-09-21` / `Sep 21, 2026` / `2026年9月21日` / `21 Sep 2026`；
  相对：`3 days ago` / `2年前` / `last week`）。**取能识别到的最新日期**，避免正文里提到的历史日期误判；
- 识别到且**早于 730 天** → 丢弃，并计数上报（"丢弃"必须可见，同 `truncate.py` 的教训）；
- 识别不到的**不丢**（无法判断 ≠ 老旧——这是"宁可放过，不可错杀"）；
- 新增参数 `include_old: bool = False`：查 GIL 是什么、JWT 结构这类 evergreen 问题时模型可显式放开。
  **这条逃生阀是必须的**，否则"2019 年那篇讲协程的文章"会被无差别枪毙，而模型不知道为什么结果变少了。

### Q5 抓到全文后过期怎么办：**标注，不丢正文**（与政策第 9 条有一处**刻意的偏离**）

政策写的是"丢弃超出时间范围的旧文档"。但**credit 已经花掉了**——丢掉正文等于钱花了、信息也没拿到，
模型只会再换一条 URL 抓，烧掉更多额度。所以推荐：

- 正文照常返回，但在**开头**打一行醒目提示：`⚠ 该页面发布时间为 2023-04-11（3 年前），可能已过时；`
  `若结论依赖它，请再找更新的来源并在回答里说明。`（13.3 节末的"正向 prompt injection"：让反馈直接驱动自我纠正）；
- `details["stale"] = True` + `published` 落审计；
- **只有完全无法判断相关性时**（正文为空 / 抓取失败）才转成 `is_error`。

请裁决：按政策原样硬丢，还是按插件标注。

### Q6 单次上限的形态：**截断 + 上报，不报错**

模型一次给 5 个 URL → 只发 2 个请求（前 2 个，即模型自己排的"top2"），
并在输出尾部写明：`本次只精读了前 2 条（上限 2）；其余 3 条未取：<url...>。确实还需要再看，请再调用一次。`
**不报错**：报错会让模型重试同一批 URL（同样的 2 条被再抓一次，白花 credit），
而截断 + 说清原因会让它做正确的下一步。

### Q7 额度账本：抽 `CreditLedger` 基类 + 会话内第二道闸

批次 7 的 `TavilyQuota` 与本次的 `FirecrawlQuota` 有约 90% 的逻辑相同
（落盘、锁、TTL 校准、预留-结算、耗尽禁用），差异只有两处：校准端点、校准响应解析。

- 判据沿用删 `BaseLoop` 时定下的那条：**"只有一个子类的抽象基类 = 纯间接"要删，而被真实出现的第二个实现所要求的抽象要抽**。
  现在第二个实现来了，所以抽 `CreditLedger`（`_credit_ledger.py`），`TavilyQuota` / `FirecrawlQuota` 各是实现子类；
  抽象方法只有两个：`USAGE_PATH`（类属性）与 `_parse_usage(payload)`。这符合 AGENTS.md 第 2 条（继承制、便于扩展）。
- **代价要说清楚**：`scripts/gate_injection_batch7.py` 的注入锚点与源码硬耦合（元纪律②），
  动了 `_tavily_quota.py` 就要**重跑 batch7 注入并修锚点**，这是本次的连带工作量（第 6 节列了）。
- **两道闸**（都推荐保留）：
  1. **全局月度**：落盘 `~/.sigma/firecrawl_usage.json`，`limit` 取服务端 `planCredits`（实测 1000），到顶禁用；
  2. **进程内**：`SESSION_FETCH_CAP = 10` 条 / 进程（可用构造函数覆盖）。防一个跑飞的 loop 在一轮任务里烧掉整月。

### Q8 CLI：`--no-web-search` 升级为"**联网工具组**总开关"

现在的语义是"关掉 web_search"。本次变成一个**能力组**（搜索 + 精读）的开关，
理由：ablation 的自变量应该是"有没有联网能力"，而不是"有搜索没精读"这种半开状态。
注册条件仍**各自独立**：有 `TAVILY_API_KEY` 才注册 `web_search`，有 `FIRECRAWL_API_KEY` 才注册 `web_fetch`
（只配一个也能用，且提示词与注册表同源——批次 7 的 G40 纪律不变，本次扩成两条断言）。

```python
# core/sigma_tools/_credit_ledger.py
class CreditLedger(ABC):
    """额度账本的公共实现。子类只需给两个东西：校准端点 + 校准响应解析。"""

    USAGE_PATH: ClassVar[str] = ""        # 例如 "/usage"

    def __init__(self, *, api_key: str, state_path: Path, base_url: str,
                 transport: httpx.AsyncBaseTransport | None = None,
                 timeout_s: float = 20.0, ttl_s: float = 300.0,
                 clock: Callable[[], float] | None = None) -> None: ...

    async def reserve(self, cost: int) -> QuotaDecision: ...   # 锁内：校准 → 判定 → 预留
    async def release(self, cost: int) -> None: ...            # 确定未在服务端发生才退
    async def mark_exhausted(self, reason: str) -> None: ...   # 服务端说用尽 → 对齐并禁用
    def snapshot(self) -> LedgerUsage: ...

    @abstractmethod
    def _parse_usage(self, payload: Any) -> tuple[int, int] | None:
        """把校准响应解析成 (used, limit)；认不出返回 None。"""


# core/sigma_tools/_tavily_quota.py
class TavilyQuota(CreditLedger):
    USAGE_PATH = "/usage"
    def _parse_usage(self, payload: Any) -> tuple[int, int] | None:
        """{"key": {"usage": 999, "limit": 1000}}（批量 7 已实测的形状）"""


# core/sigma_tools/_firecrawl_quota.py

SCRAPE_COST = 1                    # 实测：一次 scrape 后 remainingCredits 1000 → 999
SESSION_FETCH_CAP = 10             # 进程内第二道闸（Q7）
```

## 4. 四道硬闸（代码层双保险）的实现细节

### 4.1 闸一：单次抓取上限 2

```python
MAX_URLS_PER_CALL = 2          # 政策指定值，写成常量，不散落在代码里
```

`WebFetchTool.run` 的第一件事就是截断（**在扣额度之前**，所以被截掉的 URL 不会白花 credit）：

```python
urls, dropped = params.urls[: self._max_urls], params.urls[self._max_urls:]
```

`details` 里同时记 `requested` / `fetched` / `dropped_urls`——评测时可以直接查"模型平均一次点几条"，
这是"提示词是否真的让模型变克制"的**可量化证据**（不然只能靠感觉说"好像省了"）。

### 4.2 闸二：黑名单（在 LLM 之前过滤，13.5 Keep Quality Left）

```python
def is_blocked_url(url: str) -> bool:
    """命中规则：注册域精确 / 子域后缀 / 路径含 /forum/ /bbs/ /thread/。
    NEVER_BLOCK 里的权威域直接返回 False——黑名单只许漏，不许误杀。"""
```

- `web_search`：过滤发生在 `_format()` **之前**，所以被拦的结果**不进上下文**（省 token 也省误导）；
- `web_fetch`：再拦一次（纵深防御）。命中的 URL **不发请求、不花 credit**，返回 `is_error=True`
  并说明"该域名在低质量来源黑名单里，请换一个来源"。

### 4.3 闸三：时间预过滤

```python
def detect_published_at(text: str, *, now: date) -> date | None:
    """从 title + 摘要里抽最新可识别日期。认不出返回 None。

    绝对格式：2026-09-21 / 2026/09/21 / Sep 21, 2026 / 2026年9月21日 / 21 Sep 2026
    相对格式：3 days ago / 2 weeks ago / last month / 2024年3月 / 2年前
    """
```

- `web_search`：`drop_reason(...) is not None` → 丢弃 + **计数上报**；
- `web_fetch`：`metadata.publishedTime` 优先，其次正文里第一个日期；过旧 → `stale` 标注（Q5）。
- **时区/年份错觉要说清楚**：相对时间按抓取当天的 UTC 折算；`2024年3月` 这类**只有年月**的按月初算
  （结果是"可能少算了几天"，方向是**保守**——旧的更容易被丢，符合本工具的立场）。

### 4.4 闸四：额度计数器

沿用批次 7 的**预留-结算**语义（成功即已记；401/429/4xx 退回；超时/5xx 不退）：
"漏记是越界，多记只是保守"。Firecrawl 特有的两处，按官方计费表实现：

- `success: false` / 响应里没有正文 → **不计费**（官方："A scrape that returns no result is not charged"）→ `release`；
- `metadata.statusCode` 是 403/404 → **要计费**（官方："a page that responds with an error status such as 403 or 404
  ... still ... costs 1 credit"）→ 不退还，但返回 `is_error` 结果。

`SESSION_FETCH_CAP`（Q7 第二道闸）在 `run()` 里先判：超了就**不发请求**，直接返回带行动指引的拒绝
（"本次会话的抓取配额已用完，请改用已有的搜索结果摘要"——文案必须给出口，同 `truncate.py` 的教训）。

### 4.5 "丢弃必须可见"（贯穿四道闸的输出纪律）

所有被硬闸丢掉的东西，都会在 `content` 尾部留一行可读的统计：

```
[硬规则过滤：黑名单 2 条、超期 1 条；如需旧资料可加 include_old=true 重搜]
[本次仅精读前 2 条（上限 2）；未取：<url>、<url>、<url>。仍需请再调用一次。]
```

两段都刻意写进 `content`（不是 `details`）：模型看不到丢弃，就会以为"网上的资料就这么少"，
而 13.3 节末那条"让反馈直接驱动自我纠正"要求**丢了多少必须回到模型眼前**。

## 5. 政策文本（提示词）与 D4 常驻区预算

`sigma/sdk.py` 里 `WEB_SEARCH_PROMPT_LINE` 扩成两段（**仍是常量，仍是拼接**）：

```text
- web_search：联网搜索（Tavily），查本地工作区里没有的信息。返回标题 + URL + 摘要 + 可识别的发布时间。
- web_fetch：精读指定 URL 的正文（Firecrawl）。**每次最多 2 条 URL**，一次 scrape = 1 credit。

调研纪律：
1. 只采信搜索结果的条目本身；Tavily 生成的"直接答案"不可用。
2. 先说清"我要查什么"再搜；具体查询优于宽泛查询。
3. 摘要足够得出结论时**不要**精读；只在"关键结论依赖它"且"摘要不能确认"时才 web_fetch。
4. 引用任何事实必须带 URL 与文档时间；新旧来源冲突时采信更新的那条。
5. 没找到近期资料就直说"只有 X 年前的资料"，不要用旧资料假装成现状。
```

- 常驻成本：这段比批次 7 长约 250–300 token，加上 `web_fetch` 的 schema（约 150 token），
  合计 **+400 ~ +450 token**——**仍落在 D4 的 3,500 上限内，但要实测并更新 architecture 5.1 的数字**；
- 会话内**逐字节稳定**：`SessionContext` 的指纹断言照旧；开关仍然是启动时决定，会话中不变；
- `--no-web-search` 关掉时，提示词**逐字节回到 `SYSTEM_PROMPT`**（批次 7 的用例继续钉住这条）。

**三处实现判断（如实记录，与详规的差异）**

1. **`is_error` 口径在两个联网工具间不同**——web_search 是"整次调用即一个查询"，
   失败转 `is_error`；web_fetch 是"逐条报告"（每条 URL 的成败都写在 content 里），
   `is_error` 只留给"调用没执行"（取消）。理由写在 `web_fetch.run` 的注释里：
   把 401 / 额度拒绝标成 is_error 会让评测把它们当工具崩溃，而那是正常业务状态。
2. **Firecrawl 的"不退额度"类失败计入 `credits_used`**——官方计费表写明 403/404 与
   超时都可能已计费，`details["credits_used"]` 记的是"实际花了多少"，不是"成功几条"。
3. **正文预算双档**——只抓 1 条时放宽到 8000 字符（精读的意义就是拿正文），
   抓 2 条时均分 3500×2，保证第二条不会消失（`truncate_output` 8 KB 兜底）。
