# P3-批次2(追加):交互决策按键化(Tab/方向键选择)详规

> 立项:2026-09-26 ｜ 需求方:星辰 ｜ 状态:**✅ 已落地(2026-09-26,Q1=prompt_toolkit、Q2=默认"允许一次";G111–G113 全绿)**
> 前置阅读:`P3-批次2 上半场`(审批层)、`P4-批次6`(rich 渲染)

## 0. 需求原话(星辰,2026-09-26)

> 触发的 ask_user 工具列表,我希望用户可以通过 Tab 键快速切换,尽量避免用户输入;之前的同意、拒绝按钮,这种让用户决策的最好都加装这种功能。

一句话:**所有让用户决策的交互点(ask_user 选项列表、审批的 允许一次/总是允许/拒绝)统一升级为按键选择**——Tab/方向键在选项间切换、回车确认,手敲只在必要时兜底。

## 1. 范围

| 交互点 | 现状 | 改后 |
| --- | --- | --- |
| ask_user 工具 | 打印编号列表,输入序号 | 编号列表 + `›` 光标,Tab/↓↑ 切换,回车确认;Esc = 取消(回退推荐项) |
| 审批确认(危险/越界) | 提示后输入 y/a/n | 三选项选择器:`允许一次 / 总是允许 / 拒绝`,同款按键;Esc/EOF = 拒绝 |
| `/stop`、`!!`、steering 输入 | 自由文本 | 不变(不是选项型决策) |

**与"不做 TUI"决定的关系**:原决定禁的是 rich.Live/Progress 式重绘渲染与备用屏全屏界面。本批的**原位小刷新**(选项区 3–6 行,ANSI 光标上移重画)只发生在两个阻塞等人的交互点上,不属于渲染层,属于交互面——决策边界写明:**按键选择仅存在于审批与 ask_user 两处,不做任何全屏/备用屏**。

## 2. 方案

### 2.1 选择器(产品壳 `core/sigma/_selector.py`,新文件)

```python
async def select_option(
    title_lines: list[str],          # 提示/后果等静态文本
    options: list[str],              # 选项文本(渲染时带序号)
    *, recommended_index: int | None,
    input_factory = create_input,    # 注入点:测试用 create_pipe_input
) -> int | None                      # 选中下标;Esc/Ctrl+C → None(调用方决定语义)
```

- **按键表**(跨平台,由后端归一化):`Tab/↓/→` 下一项(环绕)、`↑/←/Shift+Tab` 上一项、`Enter` 确认、`Esc/Ctrl+C` 取消;数字键 1–9 直选(保留旧习惯)。
- **渲染**:首帧打印 title + 选项(选中行 `› ` 前缀 + 反色/加粗,rich Console);变化时 ANSI 光标上移 N 行原位重画。**非 TTY(stdin/stdout 任一非终端)→ 自动降级为现有编号输入模式**(broker.ask_line),评测/管道零影响。
- **纯函数核心**:`_move_selection(index, count, key) -> int | None` 单独抽出,键序逻辑离线可测。

### 2.2 接线

- **审批**:`CliApprovalGate` 的 confirmer 协议从"返回 y/a/n 字符串"升级为 `choose(title_lines, options, recommended) -> int | None`;三条选项固定 `允许一次 / 总是允许 / 拒绝`,**默认光标在"允许一次"**(常见路径直接回车;Esc=拒绝)。reject/deny 的 reason 组装不变。
- **ask_user**:cli 的 `_ask` 闭包改走 `select_option`;`ToolContext.ask` 契约不变(返回选项原文)。
- **TTY 探测**:`sys.stdin.isatty() and sys.stdout.isatty()`;非 TTY(评测/CI/管道)自动走编号输入兜底 → 现有测试与 CI 行为不变。
- 测试:`input_factory` 注入 `create_pipe_input`,按键序列(`"\t\n"`、`"\x1b[B\n"`、`"\x1b\n"`)确定性问题化;`_move_selection` 纯函数单测。

## 6. 实现记录(2026-09-26)

| 项 | 结果 |
| --- | --- |
| 选择器 | `sigma/_selector.py`:`select_option`(阻塞键循环放线程,不卡事件循环)+ `_move_selection`(纯函数,离线可测)+ `choose_option`(统一入口:真终端按键 / 非 TTY 编号降级) |
| 按键表 | Tab(CtrlI)/↓/→ 环绕下一项,↑/← 上一项,Enter 确认,数字 1–9 直选,Esc/Ctrl+C 取消(审批=拒绝,ask_user=回退推荐) |
| 审批 | `Confirmer`(y/a/n 字符串)→ `Chooser`(标题行+三选项+推荐下标,返回下标);`APPROVAL_OPTIONS` 固定"允许一次/总是允许/拒绝",默认光标 0(星辰拍板);`_render_prompt` → `_render_title`(选项区归选择器) |
| ask_user | cli `_ask` 闭包改走 `choose_option`;`ToolContext.ask` 契约不变(取消 → "" → 工具回退推荐项) |
| 依赖 | `prompt_toolkit>=3.0` 进运行期依赖(实测 3.0.53;传递依赖 wcwidth) |
| 测试 | `tests/test_selector.py` 13 条(pipe input 驱动的真实按键流);`test_approval_layer.py` 两条迁移到 chooser 协议;全套 **685 passed**、mypy --strict 61 文件零错误、lint-imports 3 KEPT、回放 **6/6** |

**踩坑记录(都是探针抓的)**:
1. prompt_toolkit 3.0.53 的 Win32PipeInput:`create_pipe_input()` 返回**上下文管理器**;`read_keys()` 无参(不带 keys 表)、**非阻塞**(无输入立即返回空表)——空转循环里 sleep+重试,独立 ESC 用 `flush_keys()` 冲出。
2. `attach()` 要求**运行中的事件循环**,而键循环跑在 to_thread 线程里 → 移除(pipe 实测不依赖;控制台输入自带读取器)。**真终端的按键路径需要人工冒烟一次**(自动测试用 pipe 注入,覆盖不了真 conhost)。
3. `KeyPress.key` 对**字符键是 str**(数字/字母),对特殊键才是 `Keys` 枚举——按 `hasattr(key, "name")` 区分。
4. 枚举 `name` 是驼峰(`ControlI`),键表是小写——循环里统一 `.lower()`(G111 纯函数测试传小写全绿、真循环全红,两处口径不一被当场抓住)。
