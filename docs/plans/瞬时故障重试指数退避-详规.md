# 瞬时故障重试指数退避——详规

日期:2026-10-06
状态:已实施(见文末 §实施记录)
拍板:星辰拍板两条——①网络原因导致的重试采用指数级退避;②最多自动重试 3 次(选项"3 次/推荐")。

## 0. 结论先行

`_stream_model` 里 transient 零产出重试从"仅 1 次、固定 1.5s"改为**最多 3 次、指数退避 1.5s→3s→6s(30s 封顶)**。重试判据语义不变(仅零产出 + 仅全 TRANSIENT),退避参数收进 frozen dataclass `TransientBackoff`,可经 `AgentLoop` 构造参数覆盖;sleep 可注入,测试不真睡、能断言延迟序列。

## 1. 现状与动机

- 现状:`src/sigma/runtime/event_loop.py` `_stream_model` 重试块硬编码 `attempts == 1` + `asyncio.sleep(1.5)`,即最多 2 次尝试、间隔恒定。
- 动机:LongCat 端点实测会挂数十秒后断连(2026-10-06 记录在 event_loop.py 注释);会话跑到第 73 轮(10m15s、2.0M token)时一次 ConnectError 重试仍失败,整轮以 error 收场。固定 1.5s 对"持续几秒~几十秒"的网络抖动救回率低——指数退避用最小代价覆盖更宽的故障时长。
- pi-harness 笔记对重试/退避无论述(全文检索仅命中约束采样一处),按 sigma 自身惯例设计。

## 2. 已验约束(决定方案形状)

1. **重试只允许发生在零产出轮**:产出过半个字再重试会让内容在消息树/钩子流出现两份(event_loop.py:677 注释)——此语义不动。
2. `signal.raise_if_cancelled()` 必须在每次 sleep 后、continue 前调用。
3. 措辞断言:`test_p0_empty_round_annotation.py:286` 只锚定"模型流式返回出错"前缀,不绑"重试 1 次"全文——动态次数安全。
4. 测试纪律:`.venv` 的 `python -m pytest`,不得并行两个 pytest 进程(README:139-147)。
5. 全仓库 LLM 层重试仅此一处;`_RETRIABLE` 里的 RATE_LIMIT 无任何消费方(429 走 error 收场),不在本次范围。

## 3. 方案

### 3.1 TransientBackoff(frozen dataclass,三问判定:无 schema/无落盘/无外部校验)

```python
@dataclass(frozen=True)
class TransientBackoff:
    max_retries: int = 3
    base_s: float = 1.5
    factor: float = 2.0
    cap_s: float = 30.0

    def delay_s(self, failed_attempt: int) -> float:
        return min(self.base_s * self.factor ** (failed_attempt - 1), self.cap_s)
```

失败第 1 次后等 1.5s、第 2 次后 3s、第 3 次后 6s;`cap_s` 在调大 max_retries 时兜底。

### 3.2 AgentLoop 注入点(与 clock/signal 先例同风格)

- `transient_backoff: TransientBackoff | None = None` → 默认 `TransientBackoff()`
- `backoff_sleep: Callable[[float], Awaitable[None]] | None = None` → 默认 `asyncio.sleep`

### 3.3 重试块改动

- 条件 `attempts == 1` → `attempts <= self._transient_backoff.max_retries`
- `await asyncio.sleep(1.5)` → `await self._backoff_sleep(self._transient_backoff.delay_s(attempts))`
- 其余不动:零产出判据、全 TRANSIENT 判据、重试前清空累积器、sleep 后 `raise_if_cancelled()`

### 3.4 措辞

`（瞬时故障已自动重试 1 次，仍失败）` → `（瞬时故障已自动重试 {attempts - 1} 次，仍失败）`——动态次数,放弃时如实报告试了几次。

## 4. 设计取舍

| 决定 | 备选 | 理由 |
|---|---|---|
| 仅 TRANSIENT 退避重试 | RATE_LIMIT 也退避 | 429 现在就没有消费方,另案拍板,不搭车 |
| 不加 jitter | 抖动防惊群 | 单客户端无惊群;确定性利于测试断言 |
| 退避在 loop 层 | provider 层重试 | 遵循"流式错误即事件、处置归上层"既有架构 |
| 注入 sleeper | monkeypatch asyncio.sleep | 全进程补丁波及同模块其他 sleep;DI 与 clock/signal 先例一致 |
