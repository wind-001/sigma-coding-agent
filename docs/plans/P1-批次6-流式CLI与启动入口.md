# P1 批次 6：流式 CLI 与启动入口

> 状态：**已实现**（2026-09-21）。
> 起因：星辰要求「支持通过主入口右键启动，在终端流式输出推理过程、工具调用，像 Pi 那样」。
> 关联：`P1-批次2-4-详规.md`（loop 形状）、`docs/architecture.md`（D4 常驻区 / D5 边界）。

## 0. 目标与边界

**要做**（三件事）：

1. **loop 可观测**：把「模型说了什么、调了什么工具、工具返回了什么」实时吐出来；
2. **终端流式渲染**：`-p` 一次性模式与交互模式都在终端逐字打印，不再等跑完才输出；
3. **一个能双击的程序入口**：不需要先 activate venv，也不需要记住 `-m` 参数。

**不做**（明确清单）：

- **不做 shell 集成（右键菜单）**——见 0.2 节的回退记录。
- **不做 TUI**（Pi 的 `pi-coding-agent` 是 TUI）。P1 只做**流式 stdout**，不做面板、不做鼠标交互、不做滚动区域。
  理由：TUI 需要把渲染与输入解耦成一整套组件，那是独立批次；而"看到过程"这个需求，流式 stdout 已经满足。
- **不做 steering / follow-up 双队列**（P3）。交互模式下输入是**同步阻塞**的：一条任务跑完才能输入下一条，中途不能插话。
- **不做落盘与压缩**（P2）。长会话必然撞上下文上限——见 R1。
- **不做多会话 / 会话切换**。

### 0.1 代价（写到明面上）

| 决策 | 代价 |
| --- | --- |
| 提前做 REPL | 此前 P1 明确「不开 REPL」（需要 steering 才有意义），**这条边界现在被部分打破**。理由从"不做假的"变为"简版 REPL 不是假的：单轮同步输入是真能用的"，但**中途打断仍然不支持**，须在使用文档里写明 |
| 流式渲染走 stdout | 无法做"只在最后展示摘要"的紧凑输出；且 `-p` 模式的过程日志与最终结果混在同一流里，脚本化消费时需要 `--quiet` 之类的开关（**本批次不做**，P5 评测运行器需要时再加） |

## 1. 关键设计决策（W9–W13）

### W9. loop 的观测接口：**单一 `on_event` 回调 + 事件对象**（建议甲）

| 选项 | 做法 | 判断 |
| --- | --- | --- |
| **甲（建议）** | `AgentLoop(observer=LoopObserver)`，观察者只有一个方法 `on_event(event)`；事件是冻结 dataclass 联合 | 新增事件类型 = 新增 dataclass，**不改接口**；P3 加 steering 时直接复用 |
| 乙 | 观察者有多个具体方法（`on_text` / `on_tool_start` / `on_tool_end`） | 每加一个观测点就要改所有实现者；扩展工具若只关心一类事件也要实现全部方法 |
| 丙 | `run_turn` 改成 async generator，产出事件流 | 形状最接近 Pi；但**改了 loop 的对外契约**——`run_turn -> TurnResult` 是当前 P2 会话树接入的前提，改它等于让 P2 跟着改。**为了渲染去动核心契约，不划算** |

**为什么事件用 dataclass 而不是 BaseModel**：文本增量**每个 chunk 一个事件**，高频创建；它们不落盘、不需要校验。
与 `TurnResult` 同一判据——**基类答"谁是谁"，模型答"装着什么"**，而事件两样都不是，它只是瞬时的通知。

**`LoopObserver` 用 ABC 且 `on_event` 给默认空实现**（不是抽象方法）。
判据与 `base.py` 一致：**空实现对所有观察者都正确**，逼每个观察者实现它只会让"只想看工具调用"的人写一堆空方法。

### W10. 交互模式形态：**简版 REPL**

- 输入用 `await asyncio.to_thread(input, ...)`，**不直接阻塞事件循环**——否则工具执行期间事件循环被卡住，流式输出会一顿一顿。
- 空行跳过；`exit` / `quit` / `:q` / Ctrl+C 退出，退出码 `0`。
- 每条输入 → 一次 `run_turn`（内部可能多轮工具调用）→ 产出消息 append 回 `SessionContext`。
  **这与一次性模式共用同一条路径**（`sdk` 里的会话对象），不另写一套组装——理由见 `sdk.py` 顶部：三处组装会各自漂移。
- **不支持中途打断**（P3）。这一条必须在启动横幅里写出来。

### W11. 什么时候进交互：**先看参数，再看 stdin，且 Windows 上不能用 `isatty`**

```
有 -p                      -> 一次性模式
有 -i                      -> 交互模式（不看 stdin 形态）
都没有                      -> stdin 是**真控制台**才交互，否则打印帮助 + 退出码 2
```

**为什么不能直接 `sys.stdin.isatty()`——这是实测出来的坑，不是理论顾虑**：
Windows 的 MSVCRT 把 **NUL 也当成字符设备**，所以 `subprocess.DEVNULL`、
`< /dev/null` 下 `isatty()` 返回 **True**。后果是 CI / 脚本里调用 `sigma`
会进 REPL 等输入——**不报错、不退出、就是卡着**。实测复现后才改成用
`GetConsoleMode`：它只对真实控制台句柄成功，对 NUL 失败。

**代价（写清楚，不藏）**：mintty（Git Bash）与管道的 stdin 不是控制台句柄，
这些环境里要交互**必须显式加 `-i`**。取舍是明摆着的——
**宁可让人多打两个字符，也不要让 CI 静默挂住。**

### W12. 启动入口：**三层外壳，零重复逻辑**

| 形式 | 场景 |
| --- | --- |
| `sigma.bat` | Windows 双击，或在 cmd 里跑 |
| `sigma.ps1` | PowerShell 终端 |
| `python -m sigma` | 通用命令行；`sigma.exe`（pip 生成的 console script）也在，但 venv 重建后可能不存在 |

三条路径通向**同一个 `sigma.cli:main`**。入口可以有多个，**组装只能有一个**——
这条与 `sdk.py` 顶那句"三处组装会各自漂移"是同一条纪律。

两个外壳各自的处理要点：

- **结尾保留窗口**：bat 用 `pause`、ps1 用 `Read-Host`。
  双击的窗口，脚本一结束就关，人什么也看不到——这是 Windows 上最经典的那个坑。
  不想等就设 `SIGMA_NO_PAUSE=1`。
- **退出码必须原样传递**（Q4：非 0 = harness 自身失败）。
  包装脚本若总是 `exit 0`，就把"sigma 崩了"悄悄改成"一切正常"。
  实测中第一版 bat 就是这么吞掉退出码的，已修。
- **参数转发**：第一个参数以 `-` 开头就全部转发给 CLI（如 `--workspace D:\code`），
  否则当作任务文本——否则 `--workspace` 这类开关根本用不了。
- bat 文件里**只用 ASCII**：cmd 按控制台 ANSI 代码页（中文 Windows 是 GBK）读 `.bat`，
  写 UTF-8 中文会变乱码；中文输出交给 Python（它自己把控制台设成 65001）。

### W13. Windows 终端编码：**启动时设 UTF-8 代码页**

`cmd.exe` 默认是 936（GBK），直接打印中文符号（`⏺`、`✓`）会乱码或抛 `UnicodeEncodeError`。
启动时：

1. `SetConsoleOutputCP(65001)`（`ctypes`，失败则跳过——Windows Terminal 下本就是 UTF-8）；
2. `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。

**`errors="replace"` 是必要的**：宁可显示一个替换字符，也不要因为一个生僻字让整次输出崩掉——
输出崩掉的代价是"整轮对话看不到"，而乱码只影响一个字符。

## 2. 事件清单（P1）

| 事件 | 时机 | 渲染 |
| --- | --- | --- |
| `TextChunk(text)` | 协议层 `TextDelta` 到达时**立即**透传 | 直接写出，不换行 |
| `ThinkingChunk(text)` | 同上（P1 的 OpenAI 兼容 provider 不产生，类型先留） | 灰色前缀 |
| `ToolStart(name, arguments, call_id)` | 参数拼装成功、执行**之前** | `⏺ grep(pattern=…)` |
| `ToolEnd(name, ok, preview)` | 单个工具返回后 | `  ✓ 前 N 字` / `  ✗ 前 N 字` |
| `TurnEnd(status, rounds, usage)` | `run_turn` 返回前 | 一行统计 |

**为什么 `ToolStart` 在执行前发、而不是执行后**：模型"决定了要调什么"本身就是过程的一部分，
而执行耗时（bash 默认上限 60 s）期间终端一片空白会让人以为卡死。

**`ToolEnd.preview` 必须截断**（复用 `truncate` 的常量思路，取前 N 字符）：
工具结果可以很大（8 KB 上限），把它整段 echo 到终端等于把上下文预算花在 UI 上。

## 4. 风险

### R1. 交互模式下长会话必然撞上下文上限（最高）

P1 无压缩（R2 of 批次 2–4 详规）。**对策**：`TurnEnd` 事件带上 `usage.prompt_tokens`，
超阈值（暂定 24,000，**批次 5 观测后校准**）时打印一行提醒，`is_error=False`——
提醒不是错误，不打断会话。

### R2. 输入阻塞与流式输出的冲突

见 W10（`asyncio.to_thread`）。若仍出现卡顿，说明某处同步 IO 卡在事件循环里，**那是缺陷不是取舍**。

### R3. 右键菜单改的是系统环境

改注册表属外部副作用。**对策**：脚本只写 HKCU、打印将写入的内容、提供幂等卸载脚本，
且**默认不自动执行**。
