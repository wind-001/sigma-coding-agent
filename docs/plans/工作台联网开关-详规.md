### 7.2 与详规的偏差（3处，都有理由）

**① 存活会话按方案 A 换掉，但用「摘掉 + 下次重建」而非「原地重建」**
详规 §3.3 推荐 A（换会话），落地时进一步简化：`_set_task_web` 只把会话从
`_SESSIONS` 摘掉，**不原地重建**。理由：原地重建要在工作台侧重复一次
`InteractiveSession` 的全部构造参数（20 个），那正是 §4.2 说的「照抄必漏参」——
摘掉让下一次 `_get_or_create_session` 走**唯一**的装配路径，多一条路径就多一份漂移。
代价如实保留：丢 steering/follow-up 队列，返回 `pendingDropped` 让 UI 显示。

**② 新增 `--web-fetch` 旗标（详规 §4.3 只列了 `--web-search`）**
`web_fetch`（Firecrawl 精读）跟 `web_search` 走同一个按钮，但它是**独立**的
key 与独立的工具。列成两个旗标是为了让「精读也能单独关」有地方可写。
`_web_flags` 里 `web_fetch` 额外要求 `--web-fetch`（默认也关）。

**③ 顺带修了一个同源漏洞（不在原详规的缺陷清单里）**
`_get_or_create_session` 换成 `build_system_prompt(memory=DEFAULT_ENABLE_MEMORY)` 后，
实测发现**记忆纪律段原本也不在工作台常驻区**——而 `enable_memory` 默认 True，
`.sigma/memory/` 扫了、索引进常驻区了，提示词却只字未提。这与联网是**同一个病**
（拼提示词时没看注册表/装配），只是没被人报出来过。
修法：`memory` 引用 SDK 的 `DEFAULT_ENABLE_MEMORY` 常量而不是写字面量 `True`
（两处各写一个字面量必然漂移）。

### 7.3 过程中实测抓到的三个 bug（都不是门写出来的，是门逼出来的）

**① 「关」路径的签名逼用户传用不上的 key**
初版 `set_web_tools(*, web_search: bool, tavily_api_key: str | None, ...)` 把
`tavily_api_key` 做成必填。实测 `set_web_tools(web_search=False)` 直接 TypeError——
而**关是默认态**，最常见的路径反而要求传一个用不上的参数。改成默认 `None`，
开启时缺 key 才抛。

**② 常驻区在往返中悄悄长出 186 字节**
重建提示词时用 `build_system_prompt` 的默认开关拼，而构造期用的是裸
`SYSTEM_PROMPT`——后者恰等于 `build_system_prompt(memory=False)`，`memory=True`
是`build_system_prompt` 的**默认值**。于是「开→关」往返后多出整段记忆纪律段，
症状是「常驻区 token 每次开关涨一点」，看着像漂移。
**根因比症状更值得记**：`system_prompt` 是调用方传进来的**成品字符串**，
本类不知道它是用什么开关拼的——所以真值不能从开关猜，只能**从成品字符串反推**。
落地为 `_prompt_flags`（用四个 `*_TOOL_LINE` 子串判定）+ `MEMORY_SECTION_MARK`。
门：`test_toggle_is_byte_stable`。

**③ 只开 `web_fetch` 时，工具表里有 `web_search`、提示词里没有**
`test_prompt_and_registry_never_disagree` 抓的。原实现分成「开/关两支」：
开的那支 `clone()` 不剔除，于是**上一次开启留下的 `web_search` 残留**。
改成「先无条件剔除两个，再按需注册」。同源纪律要求的是**逐项**对应，
不是「整体上要么有要么没有」——我写门时只想到后者，被自己的实现教育了。

## §1 根因（本批次修的真缺陷）

### 1.1 事实链

| 环节 | CLI | 工作台 |
|---|---|---|
| 解析 Tavily key | `cli/main.py:1290` `resolve_tavily_api_key()` | **零提及**（全文 grep `tavily\|web_search\|firecrawl` 无命中） |
| 传给 registry | `default_registry(web_search=web_search_on, ...)` | **不传** → `sdk.py:364` 落到 `default_registry(todo=...)` |
| registry 默认值 | 调用方显式给 | `sdk.py:150` **`web_search: bool = False`** |
| 提示词 | `build_system_prompt(web_search=web_search_on, ...)` | 裸常量 `SYSTEM_PROMPT`（`workbench_server.py:896`） |
| 最终工具表 | 含 `web_search` / `web_fetch` | **7 个**：`ask_user, bash, edit, grep, read, todo, write` |

实测取证（`.venv/Scripts/python.exe`）：

```
default_registry() → ['ask_user','bash','edit','grep','read','todo','write']
resolve_tavily_api_key()   → key=True  来源=配置文件 C:\Users\刘康鑫\.sigma\.env
resolve_firecrawl_api_key() → key=True  来源=配置文件 C:\Users\刘康鑫\.sigma\.env
SYSTEM_PROMPT == build_system_prompt()  → True（758 字节，两者都没有 web_search 行）
build_system_prompt(web_search=True, web_fetch=True) → 1222 字节（+464）
```

**key 一直在，是壳少装配了一步。** 模型没有撒谎。

### 1.2 为什么这类 bug 天生测不出来

`default_registry` 的联网开关默认 `False`，而「忘记传参数」在 Python 里完全合法、不报错——只是安静地少两个工具。
`cli/main.py:1289` 那条注释（「提示词与注册表同源」）是 CLI 自己写下的纪律，工作台**没执行它**。

### 1.3 附带缺口（同一批次）

工作台没有 CLI 那样的启动横幅（`_report_web_tool`），所以「联网工具为什么没有」在 UI 上完全不可见。
→ 本批次补一条横幅行（§4.6）。

## §3 方案总览

### 3.1 星辰已拍的两条

1. **生效时机：下次执行生效**（非立即热切）。按钮点下只记档位，当前在跑的任务跑完；下一次发消息时重建生效。
   - 依据 C2 + C5：轮中换 loop 要丢 in-flight 状态。
   - 与 `access` 的差别如实说明：`access` 能立即热切是因为它只改 gate 上的一个 `str` 属性（`_HttpApprovalGate.set_mode`），**没有换 loop**。联网要换三样东西，代价不同档。

2. **提示词联动：改 `rebuild_with_tools` 加 `system_prompt` 可选参数**（不另开方法）。

### 3.2 「默认不启动」的口径

星辰明确要**默认关**。这与 CLI 的 `web_search_on = not args.no_web_search and bool(tavily_key)`（**有 key 就开**）**方向相反**。

处置：**照 CLI 装配，只把默认值翻过来**——

```
web_search_on = flag.web_search and bool(tavily_key)
web_fetch_on  = flag.web_fetch  and bool(firecrawl_key)
```

即：**key 存在 ≠ 开启**，还要用户显式开。key 缺失时按钮显示为不可用并说明原因（不静默）。

### 3.3 数据流

```
[前端按钮 wb-composer__web]
   ↓ POST /tasks/{id}/web {"enabled": bool}
[服务端 _set_task_web]  写 _TASKS[task_id]["web"] = bool   （仅记录，不动会话）
   ↓
（下一声消息）_get_or_create_session 装配时读 record["web"]
   ↓
default_registry(web_search=..., tavily_api_key=..., web_fetch=..., firecrawl_api_key=...)
   ↓
build_system_prompt(web_search=..., web_fetch=..., ...)   ← 与 registry 同源
   ↓
InteractiveSession(registry=reg, system_prompt=prompt)
```

**存活会话怎么办**——这里有两条路，必须选：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** 换会话 | 存活的 `InteractiveSession` 从 `_SESSIONS` 摘掉，下次发消息重建 | 丢 steering/follow-up 队列（在跑的那轮已经跑完了）；换 prompt 走 `rebuild_with_tools` 的兄弟路径 |
| B 只对新建会话生效 | 存活会话永不换 | 与「access 随时切」的交互不一致，用户会困惑 |

**推荐 A**，理由：交互一致性 + `InteractiveSession` 的树/压缩视图能原样移交（`rebuild_with_tools` 已证这条路走得通），丢的只有队列。

## §4 实施清单

### 4.1 `sigma/sessions/context.py`——`rebuild_with_tools` 加可选 prompt

```python
def rebuild_with_tools(
    self,
    tools_schema: list[dict[str, Any]],
    *,
    system_prompt: str | None = None,   # None = 照抄旧（保持扩展热重载的既有行为逐字节不变）
) -> SessionContext:
```

- `system_prompt if system_prompt is not None else self._system_prompt`。
- docstring 补一句**为什么需要它**：联网开关换工具表时提示词必须同步，否则模型看到的常驻区
  自相矛盾（提示词说「有 web_search 这条工具说明」，schema 里却没有；反之亦然）。

### 4.2 `sigma/sdk.py`——`InteractiveSession` 新增 `set_web_tools`

```python
def set_web_tools(self, *, web_search: bool, web_fetch: bool,
                  tavily_api_key: str | None, firecrawl_api_key: str | None) -> None:
    """换联网工具档位（工作台「下次执行生效」的落地点）。

    重建三样：registry / context（含提示词）/ loop。依据 C1–C3。
    """
```

- registry：`clone()` 后按需 `register`（`clone` 共享工具实例、独立登记簿，2026-09-24 review 已立此形）。
- context：`rebuild_with_tools(new_schemas, system_prompt=build_system_prompt(...))` + `self._persist_hook.rebind(new)`（照抄 `reload_tools:824`）。
- loop：重建 `AgentLoop`，**逐项照抄**现有 20 个参数。**判据**：漏一个参数就是静默行为漂移——
  最容易漏的是 `tool_lock` / `mailbox_drain` / `mailbox_wait`（漏了子 agent 直接瘫）与 `ask`（漏了 ask_user 退化成自动选项）。
- 树与压缩视图：走 `rebuild_with_tools` 原样移交，不新建树。

### 4.3 `workbench_server.py`

1. `--web-search` / `--no-web-fetch`（argparse，默认**关**）。help 文案写明「默认关，需显式开启」。
2. `_get_or_create_session`：装配时读 `record.get("web")`（缺省 = 启动旗标），走 `default_registry(...)` + `build_system_prompt(...)`。
3. `_set_task_web()`：仿 `_set_task_access` 的形状（写记录 + 存活会话处理）。
4. 路由 `POST /tasks/{id}/web`。
5. 启动横幅加一行：联网工具状态 + 来源（照 `_report_web_tool` 的口径）。
6. **删掉 `system_prompt = SYSTEM_PROMPT + ...` 的裸常量用法**，改 `build_system_prompt(...)`——
   否则即使 registry 开了，提示词仍无工具行（同一个 bug 的提示词侧）。

### 4.4 前端

1. `client.ts`：`Task` 加 `web: boolean`；`setTaskWeb?()` 声明；`WEB_OPTIONS`（对齐 `ACCESS_OPTIONS` 的形状）。
