## 2. 设计

### 2.0 结构(星辰拍板 2026-09-30:协作域独立成子包)

```
sigma/team/            # 新子包:状态机 + 存储 + 信箱(纯逻辑,零 sigma 内部依赖)
├── board.py           # 迁移表 + 校验(不碰盘——纯函数,给单测直接喂)
├── store.py           # board.json 原子读写(tmp+rename + 实例级 asyncio.Lock)
└── mailbox.py         # 信箱追加 / drain-once
tools/builtin/team.py  # 薄壳:BaseTool 包装(board/send/inbox 参数模型与 is_error 结果)
```

层位:`sigma.team` 零内部依赖,与 config 并列最底层(import-linter 层表追加一行);
`tools/builtin/team.py` 向下依赖它,合法。

### 2.1 状态机(**星辰拍板:状态名 pending/running/success/fail;迁移表是规范**)

**状态**:`pending`(待认领)/ `running`(进行中)/ `success`(终态)/ `fail`(可重派)

**迁移表**(当前状态 × 事件 → 守卫 → 动作 → 次态):

| 当前状态 | 事件 | 守卫 | 动作 | 次态 |
| --- | --- | --- | --- | --- |
| (不存在) | `create(title, deps?)` | deps 全部 `success` | 分配 id、写入板 | `pending` |
| `pending` | `claim(worker)` | deps 全 `success`;未被认领 | 记 assignee=worker | `running` |
| `running` | `finish(result)` | 调用者 == assignee | 写 result | `success` |
| `running` | `fail(reason)` | 调用者 == assignee | 写 reason | `fail` |
| `running` | `reclaim(note)` | 调用者 == lead(主会话) | 清 assignee,留 note(强制接管的审计痕迹) | `pending` |
| `fail` | `reclaim(note)` | 调用者 == lead | 清 result/assignee,留 note | `pending` |
| `success` | (无出边——吸收态) | — | — | — |

非法迁移一律 `ValueError`(携带 当前状态/事件/调用者),**宁可崩不要错**。
表即代码:`board.py` 里迁移表就是一张字面量 dict,`G-TEAM-1` 逐行参数化钉住。

### 2.2 状态文件(全部落 `.sigma/team/`,回滚安全:.sigma 已在 checkpoint excludes)

- **任务板** `.sigma/team/board.json`:任务 = `{id, title, state, assignee, deps: [id], result, note}`;
- **信箱** `.sigma/team/inbox/<session-id>.jsonl`:每个 agent 一个追加写信箱。

### 2.3 派发融合(不新开机制)

- `TaskTool` dispatch 的子 agent 在 `enable_team_tasks=True` 时注册 TeamBoard;
- 主会话同时注册(主 agent 创建/分配任务);
- 派发 description 纪律:主 agent 派活时把板上的任务 id 写进 description
  (与"子 agent 不透传主上下文,需要什么由派发方给"的既有约定同源);
- **收敛**:主 agent 视角 = board.list(全局状态)+ 信箱(子 agent 消息)+
  TaskTool status(子会话进度)——三者合一看板,不新增面板。

### 2.4 预算(消费纪律:先报数字,再动表)

TeamBoard 是多 action 单工具,schema 估 200–300 token。落点优先级:
1. "工具 schema(可选:联网+task)"栏(cap 1250,实测 957,余 293);
2. 装不下 → 实测数字上报,预算修订单独提请(总额上调最小档)。
**实现完成必须回填 MEASURED 并过 G885。**

## 3. 不做(v1 显式)

角色扮演系统、跨进程/跨机(A2A)、worktree 隔离、群聊编排、自动仲裁/重派策略、
团队规模上限(子 agent 并发已有 3,够 v1)。
