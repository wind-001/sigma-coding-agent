## 3. 验收门与证据

**验收门：CI 全绿；契约能拦住一个故意写错的反向 import。**

以下为实测结果（Python 3.13.14，import-linter 2.14，mypy 2.3.1）。

### 3.1 三道门禁

```
$ lint-imports
Contracts: 2 kept, 0 broken.                     exit=0

$ mypy core
Success: no issues found in 6 source files       exit=0

$ pytest -q
3 passed                                          exit=0
```

`lint-imports` 的两条契约：
```
分层只允许向下依赖 KEPT
核心层不得依赖评测与扩展 KEPT
```

### 3.2 门槛验证：真实仓库注入违规

只证明「违规会失败」是不够的——契约配置写坏时它同样会失败。
因此做了三次实测：

| 操作 | 结果 | 退出码 |
| --- | --- | --- |
| 向 `core/sigma_ai/__init__.py` 追加 `import sigma_agent` | `分层只允许向下依赖 BROKEN` | 1 |
| 向 `core/sigma_ai/__init__.py` 追加 `import evals` | `核心层不得依赖评测与扩展 BROKEN` | 1 |
| 还原后复检 | `Contracts: 2 kept, 0 broken` | 0 |

还原后 `diff` 确认文件逐字节一致。

**结论：契约不是摆设，它真的会拦。**

### 3.3 契约测试的自证设计

`tests/test_architecture_contracts.py` 断言**两个方向**：

- `clean` fixture 必须通过 → 证明契约配置有效
- `violating` fixture 必须被拦 → 证明契约有拦截力

两个 fixture 之间**只差一个 import 的方向**，其余完全一致。
这样测试失败时原因只有一种解释。

## 4. 实施中踩到的两个坑

记录下来，避免重复踩。

### 4.1 `core/` 布局导致工具静默失效

五个包放在 `core/` 下时，`sigma_ai` 等不是顶层包名，`lint-imports` 与 `mypy`
会**静默找不到包**——不报错，只是什么都不检查。

修法（已写入 `pyproject.toml`）：

```toml
[tool.setuptools]
package-dir = { "" = "core" }

[tool.setuptools.packages.find]
where = ["core"]

[tool.mypy]
mypy_path = "core"
```

### 4.2 `forbidden` 契约引用非 root 包会报错

一开始把 `evals` / `extensions` 写进 `forbidden_modules`，但二者不在
`root_packages` 里（它们不是被安装的包），import-linter 报：

```
The top level configuration must have include_external_packages=True when there
are external forbidden modules.
```

修法：在 `[tool.importlinter]` 顶层加 `include_external_packages = true`。

### 4.3 配置位置：写在 `pyproject.toml` 而不是 `importlinter.toml`

早前在对话里说过用独立的 `importlinter.toml`。**实测 import-linter 2.14 从
`pyproject.toml` 的 `[tool.importlinter]` 读取，不需要单独文件。**
以本文件为准。
