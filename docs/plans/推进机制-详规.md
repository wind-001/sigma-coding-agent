## 0. 结论先行

1. **阶段 0 实测把体感变成了数字**（B1 基线，LongCat-2.5-Preview，22 题，N=1，
   提交号 `3fd1210`）：M1 真收束率 **20/21=95%**；M1' 谎报完成率 **1/21=5%**
   （ax107：`completed` 且 reason 为空，而判定命令 exit 1——**纯谎报，有据可查**）；
   M2 卡点自陈率 **0/2**；M3 未查证即结论率 **3/19=16%**（ax102/ax103/ax110
   首个 write/edit 前无任何 read/grep）；M4 后续步骤自发起率 **22/22=100%**；
   M5 收束轮数中位数 7。另：ax120 是 `error`（LongCat 流式挂满 302s 被双闸切掉，
   provider 网络问题，流式双闸实战兜住一次挂起）。
2. **数据改写了起点假设**（不许照抄，P7）：
   - 症状 E「每条任务都要人喂」在这批任务上**不成立**（M4=100%，多步任务
     模型都自己推进）——它不构成本批的瓶颈；
   - 原「目标延续：清单有 pending → 继续」的判据被 **2/22 的 todo 使用率**
     部分证伪：91% 的任务模型根本不建清单，该判据对它们永远不触发。
     降级为**并列的第二判据**，主判据换成**验收命令**（评测的 TaskSpec.judge
     就是现成的验收命令，ax107 这类"完成但判定挂"直接可判）；
   - 症状 A 的真实形态是 ax107 的**过早收手+谎报**（1/22）与 ax120 的
     外部 error（1/22），都不是"模型还想干但被拦"。
3. MVP 做**三个机制**，一批一个，每批自带注入实验（破坏它必须让某条断言变红）：
   - **M-B 验证收尾**（症状 A，头号）：模型宣布完成 → 跑客观判据自检
     （验收命令；清单未清空为并列判据）→ 不过 → 注入失败输出并继续一轮
     （最多 2 轮）→ 还不过 → 优雅 `stopped`+reason，**不撒谎 completed**
     （LoopControl 详规 §2.1 的 L3，当初明确不做，本次重提）；
   - **M-A 清单延续**（症状 A/E 的兜底形态）：模型收手且 todo 清单有
     pending/running → 注入清单现状并继续一轮（最多 3 轮）；
   - **M-C 正向推进注入**（症状 B）：非刹车型 steering，默认关、A/B 证明
     有效再默认开。
4. **扩展面**：推进提升为**第三类决策型钩子** `AdvanceHook`（与 `ApprovalHook`
   同模式：同一条总线、各自的名单与询问协议）。不注册 = 不干预 =
   行为与加它之前**逐字节一致**（§3）。
5. **优先级铁律**：推进永远排在刹车之后问。硬熔断 > 软检测 > 信箱兜底 >
   **推进钩子** > completed。推进只能加"还能做什么"，不能越过任何停止条件（§4）。
6. **明确不做**（§7）：bash 后台作业、子 agent 自主判断（并入提示词批次）、
   裁判模型、planner-executor 分离。写出来是为了不堆砌。

## 3. 扩展面详规：AdvanceHook（第三类决策型钩子）

### 3.1 为什么是这个形状

P3（开工指令）：`HookManager.emit()` 返回 `None`，唯一决策型钩子是
`ApprovalHook`（放行/拒绝一个工具调用），**没有任何扩展点能注入上下文，或说
"这一轮还不算完，继续"**。P4：推进机制必须提升为决策型钩子，**不是**硬编码进
`event_loop.py` / `sdk.py`。所以形状复刻 L3 审批那一套：接口定义在
`hooks/base.py`（与 `ApprovalHook` 平级），询问协议在 `HookManager`（与
`approve_tool` 平级），内置实现住上层功能域（`CliApprovalGate` 住 `security`，
内置推进判定器住 `runtime/advance.py`）。

### 3.2 接口（`src/sigma/hooks/base.py` 新增）

```python
class AdvanceHook(ABC):
    """**决策型**钩子第三类：推进——在模型没有请求的情况下，主动改变它
    下一轮能看到什么、**或是否还有下一轮**（CONTEXT.md「推进机制」词条）。

    与 ApprovalHook 的分界：审批问"这件事能不能发生"（工具执行前，
    结果是放行/拒绝）；推进问"这一轮还不算完，继续"（模型收敛时，
    结果是继续一轮/注入文本/不干预）。同一条总线，各自的名单与协议。

    异常不吞（与审批通道同判据）：推进通道本身坏了应该暴露，
    而不是静默放行——静默放行等于把"继续"的决定权偷偷交回默认路径。
    """

    name: str

    @abstractmethod
    async def advance(self, facts: AdvanceFacts) -> AdvanceDecision:
        """对一次"模型想收手"给出决定。``facts`` 是 loop 能搬的全部事实；
        "目标是否达成"的判据由实现方自取（构造时注入路径/命令），
        loop 不替它决定看什么——计算型归代码，推断型归模型。"""
        raise NotImplementedError
```

### 3.3 数据与事件（`src/sigma/events/lifecycle.py` 新增，纯数据零行为）

```python
@dataclass(frozen=True)
class AdvanceFacts:
    """问推进钩子的最小事实（三问判定：不生成 schema、不落盘、
    不校验外部输入 → frozen dataclass）。"""
    round_index: int
    last_text: str            # 模型本轮输出——它"为什么想收手"的唯一自陈

@dataclass(frozen=True)
class AdvanceDecision:
    """推进决定。默认值 = 不干预（不注册钩子时 loop 拿到 None，同效）。

    ``force_stop`` 是验证收尾的必需品：验收命令 2 轮还不过时，钩子必须能
    说"别 completed"——让它带着原因优雅 stopped（不抛异常，约束 5）。
    """
    continue_round: bool = False     # True = 模型想收手也不收，再来一轮
    force_stop: bool = False         # True = 要求优雅停止（stopped + reason）
    inject: str | None = None        # 注入给下一轮的文本（尾部 user 消息，动态区）
    reason: str = ""                 # 可指认依据——进事件与 trace，没有它不许继续/停

@dataclass(frozen=True)
class AdvanceDecided:
    """钩子点：一次推进询问的结论（审计可见——约束 4）。"""
    round_index: int
    decision: AdvanceDecision
```

### 3.4 询问协议（`HookManager` 新增两方法）

```python
def register_advance(self, hook: AdvanceHook) -> None:
    """与 register_approval 同判据：重名（含与通知/审批两名单之间）即抛。"""

async def advance_decide(self, facts: AdvanceFacts) -> AdvanceDecision | None:
    """按注册序逐个询问。

    **没有注册任何推进钩子 → None**（= 不干预，行为与加它之前逐字节一致，
    与 approve_tool 的"零审批钩子默认放行"同一条承诺）。
    多个钩子的裁决顺序（与审批"任一拒绝→拒绝"对偶，但停止权重高于继续）：
    任一 force_stop → stop（安全/验收类判据优先，不许被"再试试"盖过）；
    否则任一 continue_round → 继续（"任一认为没完 → 没完"），inject 取
    第一个要求继续的钩子的（多钩子注入打架比没有更坏）；
    全部决定连同理由进一次 AdvanceDecided 事件。
    """
```

### 3.5 loop 接入点（`runtime/event_loop.py`，`not calls` 分支内）

```python
if not calls:
    verdict = guard.end_round(...)          # 既有：刹车先判（硬熔断/软检测）
    if verdict.action == "stop": ...        # 既有
    self._todo_stall += 1                   # 既有
    tail_msgs = await self._drain_or_wait_mailbox()   # 既有：信箱兜底
    if tail_msgs:
        ...; continue                       # 既有
    # ---- 新增：推进钩子（刹车全部通过之后，唯一能说"还不算完"的地方）----
    if self._hooks is not None:
        decision = await self._hooks.advance_decide(
            AdvanceFacts(round_index=round_index, last_text=last_text)
        )
        if decision is not None and decision.force_stop:
            stopped = TurnResult(           # 优雅停止，不抛异常（约束 5）
                status="stopped", messages=produced, text=last_text,
                rounds=round_index, usage=total_usage, reason=decision.reason,
            )
            await self._emit(AdvanceDecided(round_index=round_index, decision=decision))
            await self._emit(_turn_end(stopped))
            return stopped
        if decision is not None and decision.continue_round:
            await self._emit(AdvanceDecided(round_index=round_index, decision=decision))
            if decision.inject:
                nudge = LlmMessageWrapper(                    # 与 nudge/steering 同模式：
                    timestamp=self._clock(),                  # 尾部 user 消息、不进常驻区、
                    message=UserMessage(content=decision.inject, timestamp=self._clock()),
                )
                await record(nudge, MessageInjected(message=nudge))
            continue                        # 再来一轮（下一轮开头照常过 steer/信箱/打断/护栏）
    finished = TurnResult(status="completed", ...)            # 既有路径，逐字节不变
    await self._emit(_turn_end(finished))
    return finished
```

**零值逐字节不变的三段论证**（照 `hooks/base.py` 既有承诺的格式）：
① 不注册推进钩子 → `advance_decide` 返回 `None` → 不进 if → 原路径原样返回；
② 注册了但全部不干预 → 同样不进 if；
③ 只有"注册了且至少一个给决定"才改变行为——而那一刻 `AdvanceDecided` +
（注入时）`MessageInjected` 两个事件都落盘，审计链上看得见（约束 4）。
回放与子会话不注册推进钩子，行为与没有本机制时一致（与 L3 审批同承诺）。

### 3.6 内置判定器（`src/sigma/runtime/advance.py`，MVP 做两个、各管一个判据）

**为什么两个而不是一个**：约束 1（可单独关断）——验收命令与清单是两个独立
判据，合在一个实现里就得发明组合开关（"关清单留验收"说不清）。两个钩子
各自带自己的上限计数器与注入文案，注册/不注册由调用方决定。

```python
class VerificationGate(AdvanceHook):
    """验证收尾（头号机制，治 ax107 型谎报）：模型宣布完成时跑任务的
    ``verification_cmd``（评测侧 TaskSpec.judge.command 就是现成的一例）。

    判定：工作区有 diff 且命令 exit != 0 → 注入失败输出并继续一轮；
    连续 ``max_rounds``（默认 2）轮仍不过 → ``force_stop``（stopped+reason，
    不撒谎 completed）。命令不存在/无 diff → 不干预。

    自带上上限（防死循环）：计数器在钩子实例里，**loop 不持有推进状态**
    （机制与策略分离：loop 只问决定，pi 笔记 §14.1 第 1 条）。
    验收执行期间的墙钟走 ``guard.pause()/resume()``（与审批等待同款，
    LoopGuard 已有先例）——等别人不算 agent 的空转。
    """

    name = "verification-gate"

    def __init__(
        self, workspace_root: Path, verification_cmd: str, *, max_rounds: int = 2
    ) -> None: ...
    async def advance(self, facts: AdvanceFacts) -> AdvanceDecision: ...


class GoalContinuation(AdvanceHook):
    """清单延续（并列判据，治"建了清单却没收尾"）：模型收手时读工作区
    `.sigma/todo.json`（TodoTool 的既有账本），有 pending/running →
    注入清单现状并继续一轮（最多 ``max_continues``=3）。

    基线事实：22 题里只有 2 个建了清单（9%）——所以它是**兜底判据**
    不是主判据；对不建清单的 91% 任务，验证收尾才是起作用的那个。
    """

    name = "goal-continuation"

    def __init__(self, workspace_root: Path, *, max_continues: int = 3) -> None: ...
    async def advance(self, facts: AdvanceFacts) -> AdvanceDecision: ...
```

分层核查：`runtime/advance.py` import `hooks.base`（向上）✓；读 `.sigma/todo.json`
用 `sigma.tools.builtin.todo` 的路径常量与解析（`runtime → tools` 向下 ✓，
与 `sub_agent.py` 同款依赖）；跑验收命令用 asyncio subprocess（不 import
tools 的 bash）；不 import cli/sdk/observability ✓。

## 4. 每条机制的判定口径表

优先级（命中即短路，**高层永远压过低层**——推进在最后一问）：

```
L0 用户打断（InterruptToken）            —— 既有，永远最高
L1 硬熔断（LoopGuard 五项）              —— 既有
L2 软检测停滞 nudge→stop                 —— 既有
L3 信箱兜底（子任务未回报就等/取）        —— 既有
L4 推进钩子（AdvanceHook）               —— 新增：只能在这里之后问
L5 completed / stopped                   —— 终点（stopped 由 force_stop 产生）
```

| 机制 | 默认 | 触发条件 | 误伤风险 | 与既有刹车机制的交互 |
| --- | --- | --- | --- | --- |
| M-B 验证收尾 | 关（`enable_verification_gate=False`） | 任务带 `verification_cmd` + 工作区有 diff + 模型宣布完成 | 无（没声明命令的任务完全不进场）；命令慢 → 300s 超时照 stopped；"改坏了旁边的文件"类误判由 diff 范围收窄（只跑声明了的命令，不猜） | 问在硬熔断/软检测/信箱兜底**之后**；验收等待 `guard.pause()` 不计 turn 墙钟（与审批等待同先例）；不过 2 轮后的 stopped 与护栏 stopped 同语义（reason 可辨） |
| M-A 清单延续 | 关（`enable_advance=False`） | 模型收手 + 信箱空 + `.sigma/todo.json` 有 pending/running + 连续推进 <3 | 清单写完忘了 update → 多跑 3 轮（有上限，损失封顶）；模型学会"先清清单再收尾"是**期望的**行为改变 | 同左：问在所有刹车之后；steering 计数不受影响（继续轮照常计 todo_stall） |
| M-C 正向推进注入 | 关（interval=0） | 连续 N 轮（默认 10）无 read/grep/task 推进信号 | 文案说"可以派子 agent"而注册表没有 task → 模型白调一次（**工具行与注册表同源**纪律的 loop 侧版本：按注册表现状拼文案，与 `_todo_steer_if_due` 的 `"todo" not in registry.names()` 同判据） | 与 todo steering 共用注入区与 `MessageInjected` 事件；两个间隔独立计数 |
| M-C 正向推进注入 | 关（interval=0） | 连续 N 轮（默认 10）无 read/grep/task 推进信号 | 文案说"可以派子 agent"而注册表没有 task → 模型白调一次（**工具行与注册表同源**纪律的 loop 侧版本：按注册表现状拼文案，与 `_todo_steer_if_due` 的 `"todo" not in registry.names()` 同判据） | 与 todo steering 共用注入区与 `MessageInjected` 事件；两个间隔独立计数 |

## 5. 预算与缓存影响

  信箱 / nudge / 压缩摘要同一模式：不进常驻区、不改前缀、不破 prompt cache）。

  493（全开+记忆段）= 57；核心工具 schema cap 1950 − 实测 1857 = 93。

- **trace 增长**：每次推进询问多一行 `advance` 事件（仅注册了推进钩子时）。
  TraceHook 自宽容（失败只警告+自禁用），不损任务。
