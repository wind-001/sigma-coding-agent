## 0. 需求原话（防漂移）

> 我现在想要一个 todo_list 工具，该工具旨在根据用户的目标进行任务的拆解，
> 将一个复杂的长程任务拆解成几个短程任务，提高单轮 trace 长时间 turn 之后
> 完成目标任务的可靠性。该工具具体实现将目标拆解后的任务保存在本地工作
> 文件夹维护，模型按照文件中的计划依次执行，文件中有明显的状态维护功能，
> pending / running / completed 三种状态，因此工具的设计要能够实现状态的
> 切换，功能支持断点重续，方便 trace 继续进行，可以 session 配合合作完成。
>
> （补充）10 轮 turn 没有重复调用 todo_list 获取最新进度，就强制执行调用
> ——防止多轮 turn 塞满 context 后任务跑偏。

## 1. 目标 / 非目标

**目标**：① 拆解结果持久化在工作区文件；② 状态机可切换；③ 断点重续（会话恢复后计划还在）；④ steering：连续 N 轮没碰清单就强制提醒。

**非目标**：拆解本身不靠代码（计划由模型写——**计算型归代码，推断型归模型**）；不做跨会话的 todo 合并；不做优先级/依赖图（YAGNI）。

## 2. 设计决定

### D1 文件格式与落点

`<workspace>/.sigma/todo.json`：

```json
{"goal": "...", "updated_at": "2026-09-23T13:40:00.123", "next_id": 4,
 "items": [{"id": 1, "title": "...", "detail": "...", "status": "pending"}]}
```

- **落 `.sigma/` 的硬理由**：它在 checkpoint 的 `BUILTIN_EXCLUDES` 里（checkpoint.py:45）——
  影子库回滚（`reset --hard`）**碰不到它**，断点重续天然成立；
  反之放普通路径，restore 会把"回滚点之后新建"的清单文件**删掉**。
- 时间戳走 `sigma_ai.stamps.now()`（本地毫秒，项目约定）。
- 用 JSON 不用 Markdown checkbox：状态切换要机器改写，正则改文本易碎。

### D2 工具形态：单工具三动作

`TodoTool`（`core/sigma_tools/todo.py`，name=`todo`），`action: create | update | list`：

| action | 行为 | 防呆 |
| --- | --- | --- |
| create | 全量重建（goal + items，items ≥1） | 文件已存在且未给 `overwrite=true` → **报错**（防误覆盖，与 write 不建父目录同源纪律） |
| update | 改单条：`id` 必填，`status`/`detail` 可选 | title 不可改（改标题=create+overwrite，避免歧义）；**同一时刻至多一条 running**，违反报错 |
| list | 返回渲染后的清单 + 进度统计 | 文件不存在时如实说"还没有清单"，并附 create 用法 |

- 状态机：`pending → running → completed` 单向；**同状态幂等允许**（重续场景）；
  **completed → pending 允许**（返工是真实需求，update 返回里如实报告）。
- create/update 的返回**都带全清单渲染**：模型每步都看到当前状态，操作即刷新。

### D3 steering（星辰的防跑偏需求）

- **计数器在 loop 层**（`AgentLoop._todo_stall`，实例属性，**跨 run_turn 保持**——
  loop 实例由 InteractiveSession 持有；工具层不知道"轮"，这正是它放 agent 层的理由）。
- 判据：本轮工具调用里出现 name=="todo"（**不要求成功**——模型试图看计划即是有意识）→ 清零；否则 +1。
- **挂点**：`run_turn` 轮循环体顶部（`_to_llm` 之前，loop.py:183 的预留钩子位），
  `stall ≥ interval` 时往 `produced` 追加一条 `LlmMessageWrapper(UserMessage(...))` 并清零。
  走尾部消息 = **不进常驻区、不改前缀**（D4 缓存不破，与压缩摘要降级 user 同一模式）。
- 注入文案（不带清单内容，模型自己 list——格式知识留在工具层，loop 只认工具名不 import sigma_tools）：
  `[任务清单提醒] 已连续 N 轮未查看任务清单。继续之前先调用 todo(action="list") 确认进度与下一步，防止长任务跑偏。`
- 开关：`todo_steer_interval: int = 10`（InteractiveSession / run_task 同名参数，0=关闭），透传给 AgentLoop。

### D4 常驻提示词（工具行与注册表同源，批次 7 教训）

- todo **恒注册** → SYSTEM_PROMPT 恒加一行工具行 + 「工作方式」加一条
  「长任务（≥3 步）先用 todo create 拆解计划，每完成一步 update 状态」。
- **风险**：提示词分项 cap ≤400（D4 预算表）。加行后必须跑实测脚本确认不破 cap，
  超了就精简文案，**不许涨 cap**。

### D5 断点重续与 session 的配合

- 清单在磁盘，会话树里**没有**它——压缩不碰它、恢复不用重建它。
- 恢复会话（`--continue`）后：清单文件原样在；模型首次 `todo list` 即拿到全部进度；
  steering 计数从 0 重新起算（恢复后的第一个 send，模型通常立刻看计划）。
