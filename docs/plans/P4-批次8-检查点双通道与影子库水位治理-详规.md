## 2. 设计

### 2.1 通道一:GitHub 远程通道

**快照点与影子库逐字相同**(每个写批次执行前),区别只在"提交落在哪":

```
mark():  add -A → write-tree → commit-tree → update-ref(本地影子库)
              └→ 通道一额外:git push <remote> <ref>:refs/heads/sigma/checkpoint/<session_id> --force
```

- **远程分支命名**:`sigma/checkpoint/<session_id>`——永远不碰用户的
  `main` / 已有分支;推的是备份分支,`--force` 合法(影子分支完全由本机管理)。
- **push 失败不炸**:离线 / 凭据过期 → 本地提交照旧,`last_error` 如实记录,
  横幅与状态栏展示"远程未同步";恢复在线后下一次 mark 自然补上。
- **凭据**:token 放 `~/.sigma/.env` 的 `GITHUB_TOKEN`(与 TAVILY 同一套解析);
  push 时以**进程级参数**携带(临时 URL / `http.extraHeader`),不落盘、不进
  config、不进 reflog。单用户本机假设(进程参数对同机其他进程可见,文档明说)。
- **仓库地址**:`.sigma/config.json` 的 `checkpoint_remote_url`(星辰拍板后见 Q2)。
- **家目录守门对两通道同样生效**:远程通道同样要 `git add -A` 扫全工作区,
  家目录 65s 的扫描问题不会因为换成远程而消失,且把整个家目录推上 GitHub 是灾难。

### 2.2 一个必须先说破的技术事实:远程通道做不到"零本地"

git 无法在没有本地对象库的情况下产生提交。两个可选实现:

| 方案 | 做法 | 判定 |
| --- | --- | --- |
| A. 同一影子库 + push(推荐) | 通道一 = 影子库机制照旧 + 每次 mark 后立即 push;本地库由水位治理(2.3)压住 | 离线仍有本地保障;数据以远程为准,本地只是缓存,可随时整个删掉重建 baseline |
| B. 每次快照临时建库 | temp dir init → add → commit → push → 删库 | 每个写批次付一次全量 add(家目录场景 65s × 每写批次);离线 = 完全无保护 |

**推荐 A。** 它满足星辰的真实意图——"数据不依赖这台机器":每个写批次完成后
远程已有完整副本,本地 `.sigma/` 整个删掉也不丢数据(下次启动重新基线)。
"不用本地的影子 git"在 A 下重新表述为"**不依赖**本地的影子 git"。

### 2.3 通道二:影子库治理

**(a) 位置迁移**:`.sigma/shadow.git` → `.sigma/session/shadow.git`(星辰指定)。

- 启动时若旧库存在、新库不存在 → **同分区 `os.replace` 原子改名**(O(1),
  不复制数据,回滚点零丢失);`.sigma/` 本就在 BUILTIN_EXCLUDES 里,自快照风险不变。
- 改动点只有 `shadow_git_dir_for` 一处 + 启动迁移一小段。

**(b) 水位上限**:`--checkpoint-watermark-mb`,默认 **512**(拍板 Q4)。

**(c) 超限清理(LRU,过时优先)**——触发时机:`mark()` 每 N 次 + 收尾 gc 后,
`du` 影子库目录(纯文件遍历,不做在任何写批次的热路径上):

1. **先删非当前会话的旧分支**:按分支最后提交时间从旧到新 `update-ref -d`,
   删到水位以下为止(别的会话的回滚点先牺牲——当前会话的保障不能动);
2. 仍超 → **砍当前会话老快照**:分支重建为"基线 + 最近 K 个快照"(orphan
   重放 tip tree),恢复点变少但语义保留;
3. 每轮删除后 `reflog expire --expire=now --all` + `git -c gc.packRefs=false gc --prune=now`
   (对象真释放;`packRefs=false` 是批次7 松散 ref 零进程读不变量的延续);
4. **清完仍超**(工作区本身巨大且活跃)→ 不再清,横幅警示 + `last_error`
   如实报。绝不静默丢弃、绝不放宽水位。

**(d) 回滚源**:第一版 `--rollback` 仍只从**本地影子库**恢复(离线可用);
远程是灾备副本,不是回滚源(拍板 Q6:要不要支持"本地已清理的快照从远程取回")。

### 2.4 启动询问与配置(星辰拍板 Q1)

- **交互模式 `-i`**:首次启动(无 config、无旗标)经 ask 通道问一次:
  "检查点走哪种?① 推 GitHub 远程仓库 ② 本地影子 git ③ 本次关闭",
  选择与仓库地址持久化到 `.sigma/config.json`,之后不再问;
- **一次性 `-p` / 脚本**:不问,按 config 或默认(影子);
- **旗标覆盖**:`--checkpoint-remote <url>` 强制远程、`--no-checkpoint` 仍全局关闭。
- config 读取用 pydantic BaseModel(`.sigma/config.json`),与 todo/allowlist
  同判据:工作区级状态落工作区 `.sigma/`。
