## 0. 需求原话(星辰,2026-09-26)

> 将 P1 的功能完善完毕。审批钩子触发说明:用户启动时可以选择工作目录,设置三层拦截机制,当 bash 或者编辑、写等类似的 shell 工具想要访问工作区外部环境,必须 CLI 确认,用户可以选择拒绝执行;对于一些危险指令,系统应明确给予提示以及后果;当工作执行过程,进度涉及到用户决定方向时,应实现 allowlist。

一句话:**把三层拦截补完整**——L1(写路径约束)与 L2(影子 checkpoint)已在,本批落地 L3 审批层,并让 L1 与审批联动(越界访问从"静默拒绝"升级为"确认后放行/拒绝")。

## 2. 方案

### 2.1 决策型钩子(`sigma_agent/hooks.py` 扩展)

通知型钩子(`BaseHook.emit`)是单通道的;审批是**决策点**,需要回传。新增与 `BaseHook` 并列的抽象,注册进**同一条总线**(统一管理,批次6 的方向):

```python
class ApprovalDecision(BaseModel):
    allowed: bool
    reason: str = ""              # 拒绝原因(进工具结果,模型可见)
    note: str = ""                # 批准时的说明(进结果文本)
    approve_outside: bool = False # 越界豁免:传给 ToolContext,放行 L1

class ApprovalHook(ABC):
    name: str
    @abstractmethod
    async def approve(self, name: str, arguments: dict, call_id: str) -> ApprovalDecision
```

- `HookManager.register_approval(hook)`(重名拒绝同判据)+ `approve_tool(name, arguments, call_id)`:按注册顺序逐个询问,**任一拒绝 → 短路拒绝**;全部放行 → `approve_outside` 取并集。
- **无审批钩子 = 默认放行、行为与今天逐字节一致**(评测/子 agent 不注册即静默——与渲染钩子同款承诺)。

### 2.2 loop 接线(`_execute_batch`)

`ToolStart` 发出后、执行前,对每个 planned 调用询问总线(`hooks is None → 跳过`):

- **拒绝** → 该位置填 `ToolResult(is_error=True, content="用户拒绝了这次调用:{reason}")`,不发工具、`ToolEnd(ok=False, preview="用户拒绝")`——模型可见、可自我纠正(与"单个失败不中断批次"同构);
- **批准且 `approve_outside`** → 组 `ToolContext` 时带 `outside_approved=True`;
- 批次内逐个询问(并发只读组:先全部询问再执行,保持"ToolStart 全早于 ToolEnd"的次序承诺)。

### 2.3 L1 联动(`sigma_tools/_paths.py`)

`resolve_write_path`:`ctx.outside_approved=True` 时**跳过越界 raise**(resolve/symlink 解析照做,拿到绝对路径)。其余一切不变。G64 族门槛在非交互测试路径上行为不变(见 §4)。

### 2.4 审批链(产品壳 `core/sigma/_approval.py`,新文件)

`CliApprovalGate(ApprovalHook)`,内部三级流水:

1. **allowlist 命中 → 直接放行**(不打扰);
2. **分析**:write/edit → `args.path` 相对工作区解析,越界 → 标记"访问工作区之外:{路径}";bash → 命令文本启发式(盘符/`/root`/`~/`/`../` 等)或 `cwd` 越界 → 同标记;**危险指令清单**(内置,每条带后果文案):`rm -rf /`、`rm -rf ~`、`sudo`、`dd`、`mkfs`、`format`、`curl|wget … | sh`、`git push --force`、`chmod -R 777 /`、`shutdown/reboot`、`del /s /q`、`rd /s`、`reg delete` 等 → 标记"命中危险模式 X;后果:…";**明示 6.3 的诚实声明:匹配是软边界,python -c / base64 可绕过**;
3. 无标记 → 放行(日常 ls/pytest/read 零打扰);有标记 → **confirmer**(REPL:`asyncio.to_thread(input)`——P5 已有机制,轮中暂停等输入):

```
⏺ bash 想要执行: rm -rf ~/old
  ⚠ 命中危险模式:rm -rf ~;后果:递归删除主目录下文件,删除后不可恢复(L2 快照只覆盖工作区内文件)
  允许执行?[y] 允许一次  [a] 总是允许  [n] 拒绝
```

`y` → 放行一次;`a` → 放行并写 allowlist;`n`/空/EOF → 拒绝(reason 进工具结果)。

### 2.5 allowlist

- 条目:`bash|<完整命令>`、`write|<绝对路径>`、`edit|<绝对路径>`;**v1 精确匹配**(保守:能进 allowlist 的都是被明确批准过的具体动作)。
- 落点:工作区 `.sigma/allowlist.json`(与 todo 同判据:`.sigma/` 在 checkpoint 排除清单里,回滚碰不到;项目级、人可审)。
- REPL `/allowlist` 斜杠命令:列出 / 移除(轻量可见性)。

### 2.6 CLI 接线

- REPL/`SessionManager`:每条会话注册 `CliApprovalGate`(真终端 confirmer);
- 一次性 `-p`:**非交互默认拒绝**(命中标记即拒,reason 写进结果;`--no-approval` 可整层关掉);
- 评测:不注册审批钩子 → 行为与今天逐字节一致;
- 启动横幅加一行拦截层状态:`L1 写路径 · L2 影子快照 · L3 审批(危险指令 N 条 · allowlist M 条)`;工作目录选择维持 `--workspace`(已有),横幅明示边界即"启动时选工作目录"的落地。
