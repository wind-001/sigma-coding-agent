# 开工指令：把「不灵动」改造成可证伪的推进机制

> **交付对象**：一个具备代码读写与命令执行能力的 AI 编程 agent（下称"你"）。
> **使用方式**：把本文件**整份**贴给它，工作区设为 sigma 仓库根目录。
> **本文件的性质**：开工指令（约束你**怎么想、按什么顺序做**），不是详规。
> 详规由你产出，交星辰审阅拍板后才允许动 `src/`。
>
> 本文件携带了已完成诊断的全部结论。**不要重新论证前提，不要重新定义词汇，
> 不要把它们降级成"建议"**。你的价值在于把它们变成可证伪的机制与实验。

## 0. 你面对的是什么

sigma 是自研 Python coding agent harness：Python ≥ 3.12，`src/sigma/` 共 15 个功能域
子包、97 模块、约 22k 行；1100 个单测；`mypy --strict`；`lint-imports` 两条分层契约；
21 份注入实验脚本、132 条实验。三道门禁就是 CI 的全部：`lint-imports` · `mypy src` · `pytest`。

它的设计重心是**约束**——可审计（JSONL 只追加会话树）、可回滚（影子 git checkpoint）、
可证伪（每条门槛配一次"破坏 → 断言变红 → 还原 → 断言变绿"）。这套东西做得很好。

问题出在另一面：**星辰用下来的体感是"处理任务不够灵性"，远不如参照系
deepseek harness（`@deepseek-ai/dsh`）灵动。** 诊断已完成，结论如下——这些是前提，
不是待议事项。

## 2. 词汇（用这些词，不要用同义词）

本项目 `CONTEXT.md` 已是唯一词汇表，本次新增三条，**必须沿用**：

- **推进机制**：在模型没有请求的情况下，主动改变它下一轮能看到什么、**或是否还有下一轮**。
  判据是"关掉它，任务会不会提前收束或走得更保守"。
- **刹车机制**：在模型自由推进时，判定它该停下或该收敛（硬熔断五项、软检测停滞、
  输出截断、审批拒绝、同签名失败闸）。
- **灵性**：**不是正式术语，没有判据**（答不上"怎么单独关掉它"）。

> **禁止**：在任何详规、断言、注释、commit message 里把"提升灵性""更灵动"当作判据或
> 验收标准。要写就写"某推进机制在 agency 轴上使 X 从 a 变到 b"，并给出注入实验。
> 用无判据的词写断言，必然产出名义门槛——本项目真删过一条名义门槛。

其他既有术语（常驻区、动态区、轮、任务、机制、门槛、消融档）一律按 `CONTEXT.md` 用，
不要自造。

## 5. 推进机制的设计约束（硬性）

每条新机制必须同时满足，缺一条就是不合格设计：

1. **可单独关断**：有自己的开关（`--no-*` / `enable_*` / `EvalProfile` 档位 / 构造参数），
   **没有开关的机制在本项目不算合格机制**（它答不上"怎么单独关掉它"）。
2. **零值即不变**：默认关闭或零值时，行为与加它之前**逐字节一致**。这是
   `hooks/base.py`、`AnthropicProvider`、`ShadowCheckpoint` 共同的既有纪律，沿用。
3. **不破常驻区**：注入走**动态区**（尾部 user 消息，与 steering / 信箱 / nudge / 压缩摘要
   同一模式：不进常驻区、不改前缀、不破 prompt cache）。
4. **审计可见**：注入与"继续一轮"的决定都必须经既有事件落盘（`MessageInjected` 或新增
   生命周期事件），树上原文不许被改写——会话树只追加是审计链的地基。
5. **优雅停止**：一律 `TurnResult(status=...)` + `reason`，**不抛异常**（异常会绕过树持久化）。
6. **不制造新幻觉**：任何"继续"都必须有可指认的依据。**"我觉得没做完"不是依据**；
   "验收判据不成立""清单里有 running"才是。这一条是 F4「收尾幻觉」的反面，
   不要用一个新的幻觉去治旧幻觉。
7. **类型与载体**：类型注解齐全；元数据按"三问判定"选载体——需要生成工具 JSON schema /
   需要落盘跨进程序列化 / 需要校验外部输入，任一成立用 `pydantic BaseModel`，三问皆否用
   `frozen dataclass`（详见 AGENTS.md 第 3 条）。
8. **分层不破**：新代码落在正确的功能域子包，禁止逆层引用（`lint-imports` 会红）。
   层表在 `pyproject.toml` 的 `[[tool.importlinter.contracts]]`（"分层只允许向下依赖"），
   顺序 cli → sdk → observability → runtime → tools → skills → security → **hooks** →
   sessions → memory → events → agent → prompts → config → providers → team。
   就 `hooks` 而言，**精确**边界是：
   - **不许** import `cli` / `sdk` / `observability` / `runtime` / `tools` / `skills` / `security`（都在它上层）；
   - **可以** import `sessions` / `events` / `agent` / `providers` 等下层——
     `hooks/persist.py` 就是本包里唯一碰会话的成员，这是合规的。
   第二条契约"核心包不得依赖评测与扩展"：`sigma` 任何模块都不许 import `evals` / `extensions`。

## 6. 禁区（做了就算失败）

1. **不许把"灵性/更灵动"写进断言、详规标题、验收标准。** 用 §2 的术语，给数字。
2. **不许写名义门槛**：写了断言却没有任何注入能让它红。宁可删掉那条断言。
3. **不许动常驻区预算而不先报实测数字**。`config/resident_caps.py` 写死了消费纪律：
   任何功能要吃预留，必须带自己的实测数字进这张表（像 `ask_user` 进场时报 +254 那样），
   改表必须过 `G885`。总额 5750 是数据修订的结果，不是可以随手挪的余量。
4. **不许新增"名义开关"**：一个永远不影响行为的字段比没有更坏。本项目为此**真废弃过
   一条门槛**：G57（回放工作区隔离）的注入实验 E57 实测**证伪不了它**，于是 `p21` 的
   实验表里**没有注册 G57**——"注入后仍然全绿"就是它不该当门槛的判据。照这个标准要求自己。
5. **不许为了自主性放宽安全边界**：L1 写路径沙箱、L2 影子 checkpoint、L3 审批
   **一条都不许消弱**。推进机制加的是"还能做什么"，不是"可以越过什么"。
   越界在本项目的定位是**可回滚**而不是"拦得住"，这个定位不变。
6. **不许删除或绕过既有 37 条刹车的关闭路径**。新增机制的判定顺序必须写清与它们的优先级。
7. **不许把"改完代码"当作完成**。完成判据见 §8。
8. **不许自己拍板关键点**：AGENTS.md 第 5 条——关键点的确认需要征询用户。设计上有疑问的
   地方去本地 `docs/pi-harness研究笔记.md` 找依据（839 行，尤其第 745 行"机制与策略分离"：
   核心循环只做"流式响应 → 执行工具批次 → 追加结果 → **判断是否继续**"，
   规划/审批/委派/todo 一律外置——**这正是推进机制应该外置的理由，也是你不能把
   `run_turn` 写胖的理由**）。
