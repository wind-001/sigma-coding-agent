# extensions —— 扩展样例

> 状态：P4 起填充。此处只定义约定，尚无实现。

扩展是运行时加载的 Python 模块，与内置工具**走同一套注册表接口**。
因此「用扩展替换内置工具」是免费的，`--no-builtin-tools` + 只加载扩展可直接演示。

## 边界（P4 实现时严格遵守）

扩展能做的事：

- 注册工具
- 注册钩子（`before_tool_call` / `after_tool_call` / `transform_context` 等）
- 注册 slash 命令

扩展**不能**做的事（刻意的收窄，理由见 `docs/decisions/D3-扩展层形态.md`）：

- 任意改写 harness 自身代码
- 静默覆盖内置工具（重名直接报 `DuplicateToolError`，要替换必须显式
  `--no-builtin-tools`）

## 热重载的硬约束

**调用方只能通过 `registry.get(name)` 取工具，不得缓存 `ToolDefinition` 实例。**

违反此约束的症状是「改了扩展代码但行为没变」，且极难排查。
这条约束会做成 CI 检查（见 `docs/architecture.md` 第 8 节）。

## 模块加载方式

必须每次生成新的 module 对象，**不要用 `importlib.reload()`**——
它保留同一个 module 对象，其它模块以 `from x import y` 形式持有的旧引用不会被更新。

三个必须处理的失败场景，各配一个单测：

1. 新模块导入时抛异常 → 保留旧注册表，返回失败报告，不进入半更新状态
2. 新模块没有注册任何工具 → 视为扩展被移除，清理旧注册项
3. 与内置工具重名 → 拒绝，保留旧状态

## skills/ —— 技能（2026-09-22 落地）

技能与"扩展"是**两件事**，别混：

| | 扩展（上文的 Python 模块） | 技能（`skills/` 下的 Markdown） |
| --- | --- | --- |
| 是什么 | 加**能力**（工具 / 钩子 / 命令） | 加**规范**（"这件事该怎么做"） |
| 形态 | Python 模块，运行时加载 | Markdown 文件，按需读入上下文 |
| 谁能写 | 会写 Python 的人 | 会写文档的人 |
| 进上下文吗 | 不进（只是注册） | **索引**进常驻区，**正文**按需进 |

### 目录约定

```
extensions/skills/
  image/
    image.md          ← 每个目录**恰好一个** .md
  videa/
    videa.md
```

### 文件格式

```markdown
---
name: image
description: 一句话说明「什么时候该用它」——这句话会进常驻区，要省。
---

正文……（只在模型调用 load_skill 时才进上下文）
```

- `name` 可省，缺省用**目录名**；
- `description` **必填**——索引里那一条就是靠它写的；
- `location` 由扫描自动生成（相对本目录的路径），不用手写。

### 三条硬约束

1. **一个目录恰好一个 `.md`**。多个 → 歧义，扫描器会跳过并报告。
   （正因为放宽到"那唯一的一个"，`location` 才有信息量：写死成 `<目录名>.md`
   这个字段就只是名字的复述。）
2. **坏文件会被报告，不会静默消失**。缺 frontmatter / 缺 description /
   目录里没 md —— 都会进"问题清单"，CLI 启动横幅会打出来。
   **看不见的失败是这里最坏的结果**：症状是"我加了技能它怎么不用"。
3. **正文绝不进常驻区**。它只能作为 `load_skill` 的 tool_result 追加到上下文尾部。
   违反这条 = 每加载一个技能就把之前的 prompt cache 全部作废。
   门槛 G76 钉着它（注入"把正文拼进索引"必须变红）。

### 常驻成本

索引每条约 22 token（name + description + 相对路径），**预算 ≤350 token ≈ 15 个技能**。
超过 15 个就该考虑二级索引（先列分类，再列技能）——但那是另一个设计，现在不做。
